# Anniv メディア 収益化メモ（検討用）

最終更新: 2026-08-26

**これは判断のためのメモであって、決定事項ではない。** 広告もアフィリエイトも「やる」とは決めていない。
将来どちらかを検討するときに、前提と条件を思い出すところから始めなくて済むように、
今わかっている選択肢・必要な作業・引っかかりそうな点だけを並べてある。
実際に導入すると決めたら、その時点で `メディア方針/メディア戦略.md` 側にも方針を書く。

---

## 1. 現状

- **収益導線は Anniv 本体への送客（無料相談）だけ。** 記事のCTAは `.claude/agents/reference/content-axis.md` の軸別CTAブロックで、着地点は `contact.html`（Tallyフォーム）
- **広告・アフィリエイトは1本も入っていない。** 記事に外部の収益リンクは存在しない
- `記事管理/アフィリ案件マスター.csv` はヘッダーだけの雛形が置いてある（`案件名,提携状況,トラッキングURL,バナーHTML,代表報酬,備考`）。中身は空
- `.claude/agents/reference/article-style-guide.md` の19章に、アフィリエイトリンクと広告表記のルールが**先に**書いてある（案件マスターCSVを一次ソースにする・トラッキングURLを改変しない・PR表記を必ず出す・frontmatter に `ad: true` を持たせる、など）。記事DB側も `articles.is_ad` を持っていて、CSVエクスポートの備考欄に「PR記事」と出るところまで通っている
- つまり**仕組みは先に用意してあり、案件データと判断だけが無い**状態

## 2. 判断の前提（どちらを選ぶにせよ共通）

- SEOはCVへの主力ではなく、SNSと並ぶチャネルの一つという位置づけ（メディア戦略.md 4章）。**記事の主目的は本体サービスへの送客**であって、広告収益ではない
- 立ち上げ期でPVが小さいうちは、**広告収入よりCV1件の方が桁違いに大きい**。広告を入れて記事の信頼感やCTAのクリックが落ちるなら、本業のマイナスの方が確実に効く
- 逆に「読者が最終的に外部で予約・購入する」タイプの記事（レストラン予約・ギフトEC）は、送客しても Anniv の売上にならないまま離脱している。**そこだけを収益化する**という考え方はあり得る

## 3. Google AdSense を検討する場合

### 審査に必要なもの

- **プライバシーポリシーへの追記が要る。** 現在の `public/privacy.html` 8章は GA4 と Meta ピクセルしか書いていない。AdSense を入れるなら「第三者配信の広告サービスがCookieを使用して広告を配信すること」「パーソナライズド広告の無効化（広告設定）への案内」を追記する必要がある。**追記なしで審査に出さない**
- 独自ドメイン・十分な記事数（一般に10〜30本が目安と言われるが公式の基準ではない）・運営者情報・お問い合わせ窓口。運営者情報と問い合わせは `tokutei.html` / `contact.html` で既にある
- `ads.txt` の設置（`public/ads.txt`）。無くても配信はされるが「認定販売者が不明」の警告が出る

### 入れた場合に効いてくるもの

- **CLS（Core Web Vitals）**。広告枠は後から高さが確定するので、枠に固定の `min-height` を先に確保しないとレイアウトがずれる。記事ページは今のところ計測タグ以外の外部スクリプトが無く軽いので、**入れた瞬間に一番大きく劣化するのがここ**
- 記事本文の読みやすさ。style-guide の文体・構成ルールで積み上げている「読ませる記事」の印象と、自動挿入される広告は相性が悪い
- 単価。ジャンル的にディスプレイ広告のRPMは高くない。**PVが数万/月に届くまでは金額として意味を持たない**前提で考える

## 4. アフィリエイトを検討する場合

### 候補

- **レストラン予約サイト**（一休.com・OZmall・ヒトサラなど）。軸2（記念日デート・レストラン）の記事と読者の行動が完全に一致する。ASP経由で提携できる案件があるかは未調査
- **ギフトEC**（TANP・ギフトモール系など）。軸1（ギフト・サプライズ）と一致するが、SERPで既にこれらが上位を占めているため、**同じ商品を紹介する記事で勝つ**構図になる。難易度は高い
- 記念日代行・サプライズ代行（軸3）は**自社サービスとの競合**なので、そもそも他社を紹介する意味がない。ここは今後もアフィリ対象外

### 入れるときに必ずセットにすること

- **クリック計測を同時に入れる。** 計測設計.md 9章に「爆速開発部で外部リンククリックが測れず詰まった」という失敗が記録されている。リンクを貼ってから計測を後付けする順番にしない
- `rel="sponsored"`（＋必要に応じて `nofollow`）とPR表記を、記事側の手作業ではなく**レンダラー／コンポーネント側で強制する**（同 9章）。書き手が忘れられる形にしない
- 案件データは `記事管理/アフィリ案件マスター.csv` に入れる。style-guide 19-2 のとおり、**提携状況が「提携済」かつトラッキングURLが入っている案件だけ**リンクできる
- 広告を1本でも含む記事は frontmatter に `ad: true`（ステマ規制対応。style-guide 19-5）

## 5. 今は決めないこと

- どちらを先にやるか
- 何本記事が溜まったら検討を始めるか
- 広告を入れる記事と入れない記事を分けるか（例：軸1・軸2はアフィリ可、軸3は無し）

判断の材料になるのは記事数とPVの実績なので、**記事管理（`/admin`）と PV（`pageviews` テーブル）の数字が溜まってから**改めて考える。
