## 1. 現状

- **収益導線は Anniv 本体への送客（無料相談）だけ。** 記事のCTAは `.claude/agents/reference/content-axis.md` の軸別CTAブロックで、着地点は `contact.html`（Tallyフォーム）
- **AdSense は受け皿だけ実装済み・配信はまだ0。** `src/lib/ads.ts` の `ADSENSE_CLIENT` が空のあいだは、スクリプトも枠も一切出力されない。審査が通ってIDを入れた瞬間に出はじめる
- **アフィリエイトは1本も入っていない。** 記事に外部の収益リンクは存在しない
- `記事管理/アフィリ案件マスター.csv` はヘッダーだけの雛形が置いてある（`案件名,提携状況,トラッキングURL,バナーHTML,代表報酬,備考`）。中身は空
- `.claude/agents/reference/article-style-guide.md` の19章に、アフィリエイトリンクと広告表記のルールが**先に**書いてある（案件マスターCSVを一次ソースにする・トラッキングURLを改変しない・PR表記を必ず出す・frontmatter に `ad: true` を持たせる、など）。記事DB側も `articles.is_ad` を持っていて、CSVエクスポートの備考欄に「PR記事」と出るところまで通っている
- つまり**仕組みは先に用意してあり、案件データと判断だけが無い**状態

## 2. 判断の前提（どちらを選ぶにせよ共通）

- SEOはCVへの主力ではなく、SNSと並ぶチャネルの一つという位置づけ（メディア戦略.md 4章）。**記事の主目的は本体サービスへの送客**であって、広告収益ではない
- 立ち上げ期でPVが小さいうちは、**広告収入よりCV1件の方が桁違いに大きい**。広告を入れて記事の信頼感やCTAのクリックが落ちるなら、本業のマイナスの方が確実に効く
- 逆に「読者が最終的に外部で予約・購入する」タイプの記事（レストラン予約・ギフトEC）は、送客しても Anniv の売上にならないまま離脱している。**そこだけを収益化する**という考え方はあり得る

## 3. Google AdSense（導入する）

### 決めたこと

| 項目 | 決定 |
|---|---|
| 出す場所 | **`/media` 配下の記事ページだけ。** LP（`public/*.html`）・一覧・カテゴリ・管理画面には出さない |
| 自動広告 | **使わない。** Google に挿入位置を任せるとCLSと本文の読みやすさを制御できない |
| 枠の数 | 記事末尾（CTAより下）＋ 左サイドの縦長（1440px以上でだけ出る）の**2つだけ**で始める |
| CTAとの順番 | **CTAが常に上。** 広告でCTAを押し下げない |

理由は 2章のとおりで、**立ち上げ期はCV1件のほうが広告収益より桁違いに大きい**。
広告は「読者が最後まで読んで、それでも相談しなかった人」からだけ拾う置き方にしてある。

### 実装（済み）

| ファイル | 役割 |
|---|---|
| `src/lib/ads.ts` | **SSOT。** パブリッシャーIDとスロットIDはここだけ。空＝広告を一切出さない |
| `src/components/AdSlot.astro` | 広告枠。「広告」ラベル付き。未設定なら `<ins>` も `<script>` も出さない |
| `src/layouts/MediaArticle.astro` | 枠の設置と `adsbygoogle.js` の読み込み（**記事ページのみ**） |
| `src/styles/media.css` | `.ad-inline` / `.ad-side` の `min-height`（CLS対策） |
| `public/privacy.html` | 8章に「第三者配信の広告について」を追記済み（2026-08-28） |

### 残っている手順

1. **記事を3〜5本公開する。** 記事0本のまま審査に出しても「価値の高いコンテンツがない」で落ちるだけ（公式の本数基準は無いが、実質ここが最大の関門）
2. AdSense に登録し、`https://anniv.gift` を追加する
3. 所有権の確認は **ads.txt スニペット方式**を選ぶ。`public/ads.txt` を作ってデプロイする（**メタタグ方式やコードスニペット方式だと、LP側の素のHTMLに広告用のJSを貼ることになる**ので選ばない）
4. 審査を申請する（数日〜2週間）
5. 通ったら AdSense で広告ユニットを2つ作る（ディスプレイ広告・レスポンシブ／固定サイズ160×600）
6. `src/lib/ads.ts` の `ADSENSE_CLIENT` と `AD_SLOTS.bottom` / `AD_SLOTS.side` を埋めてデプロイ
7. **PageSpeed Insights で記事ページのCLSを測り直す。** 悪化していたら枠の `min-height` を実測値に合わせる

### 入れた後に見ておくもの

- **CLS（Core Web Vitals）**。広告枠は後から高さが確定するので、`min-height` の見込みが外れるとレイアウトがずれる。記事ページは計測タグ以外の外部スクリプトが無く軽いので、**一番大きく劣化するのがここ**
- **CTAのクリック率**（`cta_click` / `line_add_click`）。広告を入れる前後で落ちていないか。落ちたら枠を減らす。広告収益よりCVが優先という順番は変えない
- 単価。ジャンル的にディスプレイ広告のRPMは高くない。**PVが数万/月に届くまでは金額として意味を持たない**前提で考える

### まだやっていない（PVが出てから判断する）

- **本文中の広告**（H2の直前など）。モバイルで一番効く位置だが、本文HTMLを分割して挿し込むことになる。`markdown.ts` が出す `:::box` / `:::faq` の入れ子を跨いで割るとHTMLが壊れるので、**やるなら保存時のレンダラー側で区切り位置を印付けする**。PVがほぼ0の今やる価値はない
- 記事一覧・カテゴリページへの広告。回遊を削る側なので当面入れない

## 4. アフィリエイトを検討する場合

### 候補

- **レストラン予約サイト**（一休.com・OZmall・ヒトサラなど）。軸2（記念日デート・レストラン）の記事と読者の行動が完全に一致する。ASP経由で提携できる案件があるかは未調査
- **ギフトEC**（TANP・ギフトモール系など）。軸1（ギフト・サプライズ）と一致するが、SERPで既にこれらが上位を占めているため、**同じ商品を紹介する記事で勝つ**構図になる。難易度は高い
- 記念日代行・サプライズ代行（軸3）は**自社サービスとの競合**なので、そもそも他社を紹介する意味がない。ここは今後もアフィリ対象外

### 入れるときに必ずセットにすること

- **クリック計測を同時に入れる。** 計測設計.md 10章に「爆速開発部で外部リンククリックが測れず詰まった」という失敗が記録されている。リンクを貼ってから計測を後付けする順番にしない
- `rel="sponsored"`（＋必要に応じて `nofollow`）とPR表記を、記事側の手作業ではなく**レンダラー／コンポーネント側で強制する**（同 9章）。書き手が忘れられる形にしない
- 案件データは `記事管理/アフィリ案件マスター.csv` に入れる。style-guide 19-2 のとおり、**提携状況が「提携済」かつトラッキングURLが入っている案件だけ**リンクできる
- 広告を1本でも含む記事は frontmatter に `ad: true`（ステマ規制対応。style-guide 19-5）

## 5. 今は決めないこと

- アフィリエイトをやるかどうか（AdSense とは独立に判断する）
- 広告を入れる記事と入れない記事を分けるか（例：軸1・軸2は広告あり、軸3＝受注直結は広告なし）

判断の材料になるのは記事数とPVの実績なので、**記事管理（`/admin`）と PV（`/admin/stats`）の数字が溜まってから**改めて考える。
