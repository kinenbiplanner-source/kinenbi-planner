## すぐやる（ダッシュボード操作。所要40分ほど）

いずれも Cloudflare / Google の管理画面での作業で、CLIからは代行できない。

### 1. Access に `/dashboard` を追加
`/dashboard` が今は403になる。Access のパスポリシーが `/admin` にしか掛かっていないため（`/admin` でログイン済みなら通る）。

Zero Trust → Access コントロール → アプリケーション → 「Anniv 管理画面」→ アプリケーションの詳細 → 宛先 → **「＋ パブリック ホスト名を追加」** → サブドメイン空欄 / ドメイン `anniv.gift` / パス `dashboard`

### 2. Search Console に sitemap を登録し直す
旧 robots.txt が `/sitemap-index.xml`（404）を指していた。**登録済みならずっとエラーになっていたはず**。

Search Console → サイトマップ → 古い登録があれば削除 → `sitemap.xml` を送信。あわせてURL検査からトップの「インデックス登録をリクエスト」（ホスティングが変わったので再クロールを促す）。

### 3. GA4 のキーイベント設定
管理 → データの表示 → イベント → `form_complete` と `line_add_click` を**キーイベントとしてマーク**。イベントは発生から最大24時間で一覧に出る。出ないときは先に DebugView で着弾確認。

### 4. www → apex の Redirect Rule
`www.anniv.gift/` と `/contact` が200を返している（`/media` 等のAstroルートは301で飛ぶ）。canonical が apex を指しているので緊急ではないが塞ぐ。

Rules → Redirect Rules → Create rule
- If: Custom filter expression → Hostname **equals** `www.anniv.gift`
- Then: Dynamic / `concat("https://anniv.gift", http.request.uri.path)` / **301** / Preserve query string にチェック

> Worker側では直せない。Astro の Cloudflare アダプタが**静的アセットを先に返してから Astro 本体を呼ぶ**ため、`/` や `/contact` には middleware が効かない（`run_worker_first` でも解決しなかった）。

### 5. Tally のリダイレクト先を確認
Tally → 該当フォーム → Settings → After submission。`https://anniv.gift/thanks.html` になっていたら `https://anniv.gift/thanks` に変更（今は307で飛ぶので動くが1ホップ無駄）。

### 6. Vercel の後片付け（2〜3日様子を見てから）
- Vercel のプロジェクトを削除
- Cloudflare DNS のワイルドカード `*` Aレコード2件と `_domainconnect` CNAME を削除（どちらもVercel由来の残骸）

## 記事を書く（最優先。他は全部その次）

基盤は完成していて、キーワードも59件がD1に入っている（`/admin/keywords`）。`priority=1` の21件から着手する。

着手順は**軸1（gift）→ 軸2（date）→ 軸3（concierge）**（メディア戦略.md 7章）。ただし**軸3はSERPがほぼ空白**（「プレゼント選び 代行 サービス」は個人向け解説が1件も存在しない）ので、軸1が3〜4本たまったら早めに取りにいく価値がある。

**勝てない領域**（調査で確定済み。ここに時間を使わない）：
- 「プレゼント おすすめ／ランキング／相場」系 → TANP・ギフトモール・伊勢丹が自社調査データで独占
- 「記念日ディナー 個室／夜景 ＋エリア」系 → OZmall・一休の予約DBが独占。**予約在庫を持たない立場では構造的に無理**

**最大の競合**：`anny.gift`（ギフトモール系）。狙い目のロングテールにガイド記事を量産中で内容も良い。正面衝突するKWは `keywords` テーブルの note に差別化方針を書いてある。

## 改良（効果が大きい順）

### A. アイキャッチ画像の運用を決める
今は全記事が「Anniv」のプレースホルダー。R2アップロードは実装済みなので、あとはテンプレを決めるだけ。**一覧のCTRに直接効く**ので記事が数本たまる前にやりたい。

### B. PVの推移グラフ　済（2026-08-26）
`/admin/stats`（管理画面ヘッダーの「メディア分析」）として実装。日次PVの棒＋7日移動平均（30日/90日切替）、記事別の直近28日 vs 前28日、軸別カバレッジ、月別の公開ペース。

- リライト候補は自動で印が付く（**下降**＝直近28日が前28日の70%未満／**伸び悩み**＝公開45日超で直近28日が20PV未満）。しきい値は `src/lib/stats.ts` の定数。立ち上げ期の暫定値なので、記事が20本を超えたら実データを見て決め直す
- 計測開始から28日たつまでは判定を出さない（古い記事が「PVが無い＝伸び悩み」に見えるため）
- ここのPVは `/api/pv` のビーコンで数えた自前の値。GA4とは必ずズレるので、突き合わせない

### C. 下書きのプレビューURL
今は公開しないと本番の見た目を確認できない。`?preview=<トークン>` で下書きを本番レンダリングで見られるようにすると、公開前チェックが確実になる。

### D. 内部リンクの自動提案
今は write-article が `KWマスターDB.csv` を見て手動で候補を出している。記事が10本を超えたあたりから、**D1の記事から関連度の高いものを自動提案する**仕組みが効いてくる。

### E. 使われなくなったCSSの掃除
メディアUI刷新で `article.css` の一部（`.article-layout` `.article-side` `.toc-card` `.badge` など）が未使用になった。記事レイアウトは `media.css` の `.art-*` に移っている。動作に影響はないが、放置すると次に触る人が混乱する。**削除前に必ず使用箇所を精査すること**（クラス名が部分一致するので単純grepでは判定を誤る）。

### F. AIクローラ設定の再判断（3〜6か月後）
2026-08-26 に Cloudflare の「管理された robots.txt」をオフにして、AI検索に拾わせる方針にした。**実際にAI経由の流入が出るか、逆に引用されず取られるだけかはデータを見てから判断し直す**。

### G. 収益化の判断
`収益化メモ.md` に選択肢と前提を整理済み。**記事数が積み上がるまで判断しない**。AdSenseを入れるならプライバシーポリシーに広告配信の記載を追加する必要がある（今の8章はGA4とMetaピクセルのみ）。
