# /anniv-update-pv｜PV更新と週次レポート（週1実行）

公開済み記事の数字を3系統（自前PV／GA4／Search Console）で取り、台帳を最新化し、
**その回の数字を読んで週次レポートを書き、ダッシュボードに載せる**。数値更新だけで終わらせない。

```
scripts/update-pv.ts ──▶ KWマスターDB.csv / PV履歴.csv / 現状ファクトシート.md
                              │
                              ▼
   Claude がファクトシートだけを読んで 週次レポート_YYYY-MM-DD.md を書く
                              │
                              ▼
scripts/update-pv.ts --publish ──▶ D1（pv_reports）──▶ https://anniv.gift/admin/stats に出る
```

**ダッシュボード（`/admin/stats`）は D1 を読むだけなので、毎週の更新にデプロイは要らない。**

## 3つの数字の読み分け（突き合わせない）

| 系統 | 出どころ | 何を見るか |
|---|---|---|
| **自前PV** | D1 `pageviews`（記事ページのビーコン） | **記事どうしの相対比較**。自動判定（下降／伸び悩み）の基準 |
| **GA4** | Data API（サービスアカウント） | 流入チャネル・滞在時間。「誰がどこから来たか」 |
| **Search Console** | Search Analytics API（同じ鍵） | **検索での立ち位置**。表示・順位・CTR。立ち上げ期はPVより先に動く |

3つは計測方式が違うので必ずズレる。ズレを埋めようとしない（`src/lib/ga4.ts` 冒頭と同じ立場）。
CV（`form_complete` / `line_add_click`）は D1 `event_daily` から取る。**PVは手段で、本命はCV**（メディア戦略.md 6章）。

---

## 1. スクリプトを回す

```bash
node --experimental-strip-types scripts/update-pv.ts
```

`$ARGUMENTS` に `--dry-run` があればそのまま付ける（取得と表示だけ。ファイルは書かない）。

やること（順序固定。1が失敗したら止まる。2・3は取れなくても続く）：

1. **D1（本番）** から記事・自前PV・導線イベントを引く（wrangler 経由＝ put-draft.ts と同じ経路。Access を開けない）
2. **GA4** から `/media/` 配下のページ別PV・滞在・流入チャネル（直近28日）
3. **Search Console** から `/media/` 配下のページ別・クエリ別のクリック・表示・順位（直近3日は未確定なので外した28日）
4. 書き出し：
   - `記事管理/KWマスターDB.csv` — D1 の全記事で丸ごと再生成。列は `/api/export.csv` と同じ（従来9列＋累計PV／直近28日／前28日／増減／判定（自動））
   - `記事管理/PV履歴.csv` — 日付スナップショット（同日に何度回しても上書き。前回比の基準）
   - `記事管理/PVレポート/現状ファクトシート.md` — **毎回まっさらに再生成。次のステップの唯一の入力**

**GA4・GSC がスキップされたとき**（`.dev.vars` に鍵が無い／GSCに権限が無い）は、その旨を1行ユーザーに伝えて続行する。
設定手順は `メディア方針/計測設計.md` 11章の「6. ローカルからも叩く」。止まらない。

## 2. 週次レポートを書く（毎回・必須。ここが本体）

スクリプトが終わった時点で `現状ファクトシート.md` に今回の全データが入っている。

### 入力は1つだけ

**`記事管理/PVレポート/現状ファクトシート.md` を読む。これが唯一の分析インプット。**
計測の状態・全体サマリー・軸別・記事別ランキング（自前PV／GA4／GSC／自動判定）・流入チャネル・導線とCV・GSCクエリ（取りこぼし／striking distance／記事別上位）・前回比（機械計算）が全部入っている。

**前回の `週次レポート_*.md`・過去のファクトシート・`/admin/stats` は開かない。** 開くと前回の文章の焼き増しになる。

### 出力

`記事管理/PVレポート/週次レポート_YYYY-MM-DD.md`（日付はファクトシートの見出しの日付）。**この形で書く**：

```markdown
# 週次レポート YYYY-MM-DD

## サマリー
（3行以内。今週の数字が何を意味するか。数字はファクトシートから拾って書く）

## 集客
（検索：GSCの表示・順位・取りこぼし・striking distance の読み。SNS：チャネル別セッションと流入元別イベント。
　GA4/GSCが取れていない回は「取れていない」と1行で書き、自前PVと導線だけで読む）

## 記事別の判定

| KW | 判定 | 根拠 | 次の一手 |
|---|---|---|---|
| … | 様子見／維持／リライト／統合・取り下げ検討 | ファクトシートの数字 | 具体的に1つ |

## 導線・CV
（CVの件数・発火場所・流入元。本命指標なので、0件でも「0件」と書いて、導線のどこで止まっているかを読む）

## 打ち手（次の1週間・3つまで）
1. …
```

### 書き方のルール

- **「今この数値が何を意味するか・だから次に何をするか」だけを書く。** 数字の羅列はファクトシートにあるので繰り返さない
- **前回比は書かない。** 総PVの増減・伸びた／落ちた記事は「前回比」節が機械で出している。差分に触れるのは**差分で解釈や打ち手が変わるときだけ**。「前回から不変」「顔ぶれは同じ」式の使い回し文は禁止
- **立ち上げ期の読み方**：PVが2桁のうちは1〜2件の差を読まない。**最初に動くのはGSCの表示と順位**なので、検索の立ち位置を主役にする。CVは0でも書く
- **判定の語彙は4つだけ**：`様子見` / `維持` / `リライト` / `統合・取り下げ検討`（目安は下の表）。**計測28日未満、または公開45日未満の記事は `様子見` で固定**——数字が無いのに判定を出すと、次回の自分がその判定を根拠にする
- 記事は必ずKWで名指しし、根拠の数字はファクトシートから拾う。「一部の記事」「いくつかのKW」と書かない
- 記法は `##` `###` `- ` `**太字**` 表だけ。**`:::` のコンテナと `[[toc]]` は使わない**（ダッシュボードが記事と同じレンダラーで描くため）。H1はタイトル行の1つだけ（画面では非表示になる）
- 長さは**60行以内**。ダッシュボードのカードに丸ごと出るので、読み切れる量にする
- 戦略の骨子を動かす話（軸の順番・KPIの置き方）が出たら、それは `メディア方針/メディア戦略.md` 側で扱う。レポートは「今の数値とその読み」に集中する

---

## 3. ダッシュボードに載せる

```bash
node --experimental-strip-types scripts/update-pv.ts --publish "記事管理/PVレポート/週次レポート_YYYY-MM-DD.md"
```

レポート本文と、その日の記事別 GA4／GSC の断面（`PV履歴.csv` から）を D1 の `pv_reports` に入れる。
`https://anniv.gift/admin/stats` を開けば「週次レポート」カードと、記事別テーブルの右に GA4・GSC の列が出ている。
**デプロイは要らない**（画面は D1 を読むだけ）。同じ日に何度入れても1件に上書きされる。

---

## 4. 出力の見せ方

実行後、ユーザーには次の順で見せる：

1. **記事別ランキング**（スクリプトの出力そのまま。自前PV 直近28日 順に GA4／GSC／判定／公開日が並ぶ）
2. 全体の一言：直近28日PV（前期・増減）、計測何日目で自動判定が出るか、**CVの件数**
3. GA4・GSC が取れたか。取れていなければ設定の1行（計測設計.md 11章）
4. **記事別の判定表**（レポートの該当節をそのまま）と打ち手
5. 書いたファイルと、`/admin/stats` に載せた旨

## リライト判定の目安

自動判定（下降／伸び悩み）は `src/lib/stats.ts` の定数で機械が出す。レポートの判定はそれに GSC と経過日数を重ねて人（Claude）が出す。

| 判定 | 目安 | 対応 |
|---|---|---|
| **様子見** | 計測28日未満／公開45日未満／GSCにまだ表示が付いていない | 触らない。内部リンクの受け皿にだけ使う |
| **維持** | 自前PVが上位で減っていない／GSC順位が上がっている | 関連KWで記事を足す・内部リンクで送客先（軸3・無料相談）へ橋を架ける |
| **リライト** | 公開45日超で直近28日 <20PV（自動「伸び悩み」）／GSCで表示はあるのに CTR <2%（タイトル・ディスクリプション）／順位4〜20に表示が溜まっている（加筆・内部リンク） | `/anniv-rewrite-article <KW>` |
| **統合・取り下げ検討** | 公開90日超で表示もPVもほぼゼロ／近いKWの記事と食い合っている | 統合か301。**URLは変えない・消さない**（爆速側で評価リセットの実害） |

優先順位：①GSCで表示があるのにPVに変わっていない記事（タイトル直しで一番早く効く）→ ②striking distance に溜まっている記事（加筆で1ページ目に乗る）→ ③公開45日超で動かない記事 → ④その他。

`KWマスターDB.csv` の `判定（自動）` 列は機械の値で、人の判定で上書きしない（CSVは D1 から再生成されるので、書いても次回消える）。**人の判定はレポートに書く。**

## メモ

- **PVのSSOTは D1**（`pageviews`）。`KWマスターDB.csv` は D1 から吐き出す派生物で、手で編集しない（管理画面の「CSVエクスポート」でも、このスキルでも、同じ列で丸ごと上書きされる。列の定義は `src/lib/kw-csv.ts`）
- **記事を公開した直後にも回してよい**（台帳の最新化だけが目的なら `--dry-run` 無しで回して、レポートは書かなくていい。その場合はユーザーにそう伝える）
- GA4・GSC の鍵は `.dev.vars`（gitignore 済み）。Worker に `wrangler secret put` した3変数と同じ値＋任意で `GSC_SITE_URL`（既定 `https://anniv.gift/`。ドメインプロパティなら `sc-domain:anniv.gift`）。サービスアカウントなので **7日で失効しない**（爆速側のOAuthとは違う）
- GSC はサービスアカウントをプロパティの「ユーザーと権限」に追加し、GCP で Search Console API を有効にしないと 403。手順は `メディア方針/計測設計.md` 11章
- しきい値（GSCの取りこぼし・striking distance）は `scripts/update-pv.ts` 冒頭の定数。**立ち上げ期用に低く置いてある**（表示≥20・CTR<2%／順位4〜20・表示≥5）。表示が3桁に乗ったら上げる。自動判定のしきい値は `src/lib/stats.ts`
- `/admin/stats` に出るのは最新の1件だけ。過去分は `記事管理/PVレポート/週次レポート_*.md`（書くときは開かない。振り返りたいときだけ）
- ローカルの D1（astro dev）に対して試すときは `--local`
