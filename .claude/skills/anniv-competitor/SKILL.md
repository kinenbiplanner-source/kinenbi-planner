# /anniv-competitor｜競合の観測

同業（Instagram 3タイプ＋競合サイト）の**伸びている投稿・記事**を取って読み、
Anniv のネタ（`記事管理/SNSネタ台帳.csv`）と KW候補（`/anniv-pick-keyword` の種）に変換する。
`/anniv-sns-batch` と同じ週の前半、**隔週**で回す。

```
scripts/seo/ig-scan.ts ──▶ 記事管理/競合/IG観測_<日付>.md
scripts/seo/site-scan.ts ─▶ 記事管理/競合/記事観測_<日付>.md（末尾に種KW候補）
                     │
                     ▼
このスキルが読んで翻訳 ──▶ 記事管理/競合/レポート_<日付>.md
                     │
                     ▼（停止点）
        SNSネタ台帳.csv に足す行をユーザーに確認
                     │
                     ▼
        /anniv-sns-batch ／ /anniv-pick-keyword <軸>
```

**自分で実行：Step 0〜3・5**（対話・スクリプト実行・翻訳・レポート生成・引き継ぎ）
**ユーザー対話・停止点：Step 4のみ**

## 前提（読む順に）

| ファイル | 何のため |
|---|---|
| `メディア方針/SNS戦略.md` 3章「競合の観測」・4章「伸びている投稿の分解」「勝ちパターン6則」 | 分析の物差し。SSOTなので**転記しない** |
| `記事管理/競合/targets.json` | 観測対象（IGアカウント・競合サイト・ハッシュタグ）。**人が編集するのはこのファイルだけ** |
| `記事管理/SNSネタ台帳.csv` | ネタのSSOT。列は `idea_id,工程,状況,失敗,軸,一次知見,出典,X使用日,Threads使用日,反応` |
| `.claude/agents/reference/keyword-selection.md` 5章 | KW候補に落とすときの除外ルール |
| `.claude/agents/reference/content-axis.md` | 軸1（gift）／軸2（date）／軸3（concierge）の定義 |
| `.claude/skills/anniv-sns-batch/SKILL.md` | ネタ台帳の使い方（「守る3つだけ」）。Step 4 の行の作り方はこれに揃える |

**`article-style-guide.md` は読まない。** SNS側の判断はSNS戦略.md、記事側の判断はkeyword-selection.md／content-axis.mdに従う。

## 注意事項（全Stepに効く）

- **規約・フォロワー数で比べない。** 見るのは「同じアカウント内でどの題材が伸びたか」（中央値比）。フォロワー数が違うアカウント同士を数字で比べない
- **競合のキャプション・文面をそのまま写さない。** 題材（誰の・どんな状況の・何個）だけ抜き、言葉はAnnivの声で書き直す
- **実績の量・年数を暗示する表現を使わない**（`メディア方針/メディア戦略.md`・軸3の運用ルールと同じ。立ち上げ期のAnnivが「多数の実績」を語ると事実として嘘になる）
- **Hashtag Search は使わない。** App Review（Public Content Access）が要るので現状は対象外。`targets.json` の `hashtags` は Business Discovery 経路が対応するまで温存するだけ
- **`targets.json` 以外は手で編集しない。** 観測対象の増減はレポート末尾で提案するだけ（Step 3 ⑤）。反映は人が `targets.json` を直す

## 作業フロー

### Step 0：観測対象の確認（自分で実行・停止しない）

`記事管理/競合/targets.json` を読み、`active` な `accounts`（IG）と `sites`（競合サイト）を確認する。
引数で `ig` / `sites` が指定されていれば片方だけ、`all`（既定）なら両方進める。

増減の判断はここではしない。気づいたこと（更新が止まっている・新しく目立つアカウントがある等）は Step 3 ⑤ に送る。

### Step 1：取得（自分で実行・停止しない）

**(a) Instagram**

```bash
node --experimental-strip-types scripts/seo/ig-scan.ts --limit 30
```

`.dev.vars` に `IG_GRAPH_TOKEN` / `IG_BUSINESS_ID` が無ければ API を飛ばして終わる。その場合は
「Instagram観測は鍵が無いため飛ばした（設定手順は `メディア方針/SNS戦略.md`「競合の観測」）」と1行残し、
**手動の繋ぎ**を案内する：

```bash
node --experimental-strip-types scripts/seo/ig-scan.ts --template   # 埋める形のJSONを出す
# ユーザーがIGアプリで数字を見て埋めたら
node --experimental-strip-types scripts/seo/ig-scan.ts --import <埋めたJSONのパス>
```

いずれの経路でも `記事管理/競合/IG観測_<日付>.md` が出る。

**(b) 競合サイト**

```bash
node --experimental-strip-types scripts/seo/site-scan.ts --days 30
```

`記事管理/競合/記事観測_<日付>.md` が出る（末尾に「種KW候補」）。

**(c) Ahrefs（繋がっていれば）**

`ToolSearch` で `ahrefs` を検索する。

- 見つかれば Site Explorer 系（top pages / organic keywords）で `targets.json` の `sites` の上位ページを取り、
  `記事管理/競合/<日付>_ahrefs.json` に `{"<url>": {"traffic": 1200, "top_keyword": "…"}}` の形で書く。
  Content gap が取れるなら `記事管理/競合/<日付>_gap.json` も書く
- 取れたら `site-scan.ts --ahrefs 記事管理/競合/<日付>_ahrefs.json` で読み直し、記事観測に伸びの数字を乗せる
- **認証待ち**（セッション開始時に「require authentication: ahrefs」の案内が出る状態）なら、
  「対話セッションで `/mcp` から ahrefs を認証してから再実行」と1行伝えてこの回は諦める（待たない）
- **Ahrefs が無い／未認証のときは明記する**：「伸びは分からない。何を書き足しているかだけ分かる」
  （`site-scan.ts` の新着・更新は取れるが、それが伸びているかはAhrefsが無いと判断できない）

`--no-fetch` が指定されていたら Step 1 を丸ごと飛ばし、`記事管理/競合/` にある**直近の** `IG観測_*.md` と `記事観測_*.md` を読んで Step 2 に進む。

### Step 2：読む（自分で実行・停止しない）

物差しは `メディア方針/SNS戦略.md` 4章（伸びている投稿の分解・勝ちパターン6則）。**中身は転記せず、当てはめた結果だけ書く。**

**(a) 伸びた投稿の題材をAnniv版に翻訳する**

`IG観測_<日付>.md` から、同じアカウント内で中央値の3倍を超えた投稿（無ければ上位から数本）を抜く。1本ごとに：

- 題材（誰の・どんな状況の・何個）だけを抜く。**キャプションの言葉は写さない**
- Anniv版の企画に翻訳する条件（3つとも満たすものだけ採用候補にする）：
  1. **実績を語らない**（競合が「〇〇選」で並べる商品紹介型は、Annivが同じ型をやると軸6則の独壇場から外れる）
  2. **提案そのものを実演する**（SNS戦略.md 4章「フォーマットA」の型に寄せられるか）
  3. **規則6の独壇場に必ず1つ接続する**——店に頼めること・締切・予算の内訳・段取り・店に送る文面のどれか1つ

**(b) 独壇場フラグ**

競合の投稿・記事が上の独壇場領域（店に頼めること・予算内訳・段取り・文面）に踏み込んでいたら、
「競合が入ってきた領域」として Step 3 ③（警戒）に上げる。

**(c) 記事側：種KW候補**

`記事観測_<日付>.md` 末尾の「種KW候補」と、Ahrefsが取れていれば上位ページの `top_keyword` を集め、
`keyword-selection.md` 5章の除外ルールを当てて残ったものを**種KW（3〜6語）**の形に整える。
競合サイトの記事タイトルと自社KWマスターDBを見比べ、**同じ題材を競合だけが持っている**ものはリライト候補として別枠にする。

### Step 3：出力（自分で実行・停止しない）

`記事管理/競合/レポート_<日付>.md` を書く。

```markdown
# 競合観測レポート <日付>

## ① 要点（3行）
- ...

## ② 伸びた投稿とAnniv版の企画

| 競合の投稿（リンク） | 中央値比 | 題材 | Anniv版のフック案 | 工程 | 状況 | CVへの接続（1行） |
|---|---|---|---|---|---|---|
| [@handle](permalink) | 3.2倍 | ... | ... | 買う・予約する | 誕生日 | ... |

## ③ 警戒
- （独壇場に競合が踏み込んだ領域があれば）...
- なければ「今回は無し」と明記する

## ④ 記事側
**種KW候補**
```
（改行区切りで3〜6語ずつ）
```
**被っている題材（リライト候補）**
- ...

## ⑤ 観測対象の増減の提案
- （新しく目立つアカウント／更新が止まったサイトがあれば）...
- なければ「今回は無し」と明記する

## ⑥ やらないもの
- （フォロワー数だけが理由で真似しない企画・独壇場に接続できない題材など）
```

Ahrefsが無かった回・IG観測を手動で繋いだ回は①の直後に1行ずつ添える。

### Step 4：ネタ台帳へ（ユーザー対話・唯一の停止点）

Step 2(a) で採用候補にした企画を、`記事管理/SNSネタ台帳.csv` に足す行の形で表にして見せる。

| idea_id | 工程 | 状況 | 失敗 | 軸 | 一次知見 | 出典 |
|---|---|---|---|---|---|---|
| （英小文字とハイフン） | （既存値から選ぶ） | （既存値から選ぶ） | （既存値から選ぶ。無ければ空欄） | 1/2/3 | （Annivの言葉で書き直したもの） | 競合 @<handle> <permalink> |

作り方の注意：

- **`工程`・`状況`・`失敗`は台帳に既にある値に揃える**（新しい値を作らない。無ければ空欄でよい列は失敗のみ）
- **`一次知見`は競合の題材をAnnivの視点で書き直したもの。** 競合のキャプションの言い回しをそのまま使わない
- **`出典`は `競合 @<handle> <permalink>` の形**（自問自答由来・X原稿バンク由来の既存行と区別がつくように）
- `使用日`・`反応`は空欄のまま

AskUserQuestion で選ばせる：「全部入れる／選ぶ／入れない」。「選ぶ」なら個別に採否を聞く。

承認された行だけ CSV に追記する。**列順・既存行・エンコーディングは変えない**（追記のみ。既存行を並べ替えたり書き換えたりしない）。一次知見や出典に読点以外のカンマが入る場合は、その値だけダブルクォートで囲む。

### Step 5：引き継ぎ（自分で実行・停止しない）

台帳に行を足したら、次を提示する：

- `/anniv-sns-batch`（足したネタが次回バッチの空きマス埋めに使える）
- `/anniv-pick-keyword <軸>`（Step 2(c) の種KW候補を渡す）

Step 1 で鍵が無く飛ばした取得（IG／Ahrefs）があれば、末尾に1行ずつ「次回までに繋げば実データで判定できる」と添える。
