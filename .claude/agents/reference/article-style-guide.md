# Annivメディア・記事スタイルガイド（SSOT）

Annivメディアの記事制作における**ルール本体**。執筆エージェント（article-writer）・レビューエージェント（article-reviewer）が共通参照する。

> 爆速開発部メディアの同名ファイルをベースに移植。骨格・SEO・装飾・チェックリスト等の共通ルールは軸を問わず流用できるため実質そのまま。固有名詞（メディア名・軸・禁止ワード・例文）のみAnniv向けに調整した。

**ルール変更はこのファイルのみ修正する**。writer/reviewer側にはルールを書かない（プロセス・役割定義のみ）。

---

## 0. コア原則（最初に必ず確認）

**このメディアの声＝「記念日のプランを一緒に考えている人」**。友人の相談に落ち着いて答えるトーンで、親しみやすく寄り添いながら、事実と判断軸は言い切る（8-0章）。**共感の一文と読者への呼びかけ（「あなた」も可）は積極的に使う**——制限するのは同じ言い回しの反復とポエム・押し売りだけ。この声を外した記事は、他がすべて合っていても直す。

詳細は各章。まずこの10個を頭に入れてから書く・直す。違反が多い順。

1. **自己言及・看板ワードを1個も出さない**（「代行会社」「弊社」「〜の視点で」等）。最優先（2章）
2. **H2は5〜7個**（総合ガイド記事のみ例外）。8個以上は統合（7章）
3. **見出し直下は1〜3文**、直後にカスタムブロックを直置きしない（3章）
4. **まとめH2を最後に必ず置く**（結論を含む見出し＋要点ボックス＋行動提言）（5章）
5. **導入は課題共感型→冒頭100字にメインKW→`:::summary`（結論の箇条書き）必須**（4章）
6. **事実は断定・気持ちは受け止め**。AI臭・誇大・事務的な硬さ・ポエムをどれも避ける（「現実解」「正直」「体感」／「大切な人のために」等を乱用しない）（8章）
7. **数値・料金・仕様は一次情報リンク＋時制明示**（12章）
8. **装飾を積極的に使う**（表・箇条書き・ラベルボックス・カード）。蛍光ペンマーカー（`==テキスト==`）はH2ごとに1箇所だけ・配下H3の最重要箇所に置く（9章）
9. **外部リンクは公式・一次情報のみ。「こちら」誘導NG**（11章）
10. **アフィリは原則オフ。ユーザー指定時のみ・指定URL・差し込み位置・広告表記を守る**（19章。アフィリを含む記事のみ）

出力前（writer）／レビュー時（reviewer）は必ず **18章の統合チェックリスト** を通す。

## 1. ペルソナと読者レベルの判断（検索意図ベース・全軸共通）

**ペルソナは固定しない。記事ごとに「検索意図」から読者レベルを判断する**。このスタイルガイドのルールは**全コンテンツ軸で共通**——骨格・文体・装飾の本体は軸で変えない。軸（記念日ギフト・サプライズ / 記念日デート・レストラン / 記念日代行・サプライズ代行サービス 等）で変わるのは「リサーチ観点」と「文体の寄せ」だけで、その定義は `content-axis.md`（SSOT）にある。読者レベルと深度は検索意図から判断する。

### 1-1. 検索意図から読者レベルを決める

competitor-researcher の検索意図マップ（顕在・潜在ニーズ／検索者の状況・前提知識）を見て、その記事の読者レベルを判断し、文体と深度を合わせる。検索意図マップが無いときはKWから意図を推定する。

| 検索意図のタイプ | 主なKWパターン | 文体・深度の合わせ方 |
|---|---|---|
| 入門・基礎 | 「とは」「選び方」「意味」「相場」 | 噛み砕き多め・専門用語（花言葉・演出用語等）に説明を添える・前提知識を要求しない |
| 比較・検討 | 「比較」「おすすめ」「予算別」「違い」 | 判断軸を明快に・結論ファースト・表で整理 |
| 実践・段取り | 「頼み方」「渡し方」「予約」「当日の流れ」 | 実践観点・段取り・落とし穴まで踏み込む・手順は番号付きで具体的に |

同じKWに複数の意図層があるときは、顕在ニーズの中心層に文体を合わせ、潜在ニーズは補足で拾う。

### 1-2. 共通方針（全記事）

- 「で、結局どうすればいいの？」に答える構成
- 記事の最終ゴール：読者が次のアクションを取れる状態にする
- 表面的な比較・まとめは避け、**上位記事より一段深い切り口を「内容で」示す**（差別化ポイントを反映。看板ワードは出さない＝2章）
- **読者に直接呼びかける**（「あなた」も使ってよい）。共感の一文も積極的に入れる。ただし同じ言い回しを繰り返さない（8-1章）
- 読者の迷いをいったん受け止めてから判断材料を出す（順序を逆にすると冷たく読める。8-0章）

## 2. 自己言及・看板ワード完全禁止（最優先ルール）

記事の構成・切り口・判断軸には作る側としての視点を反映する。**ただし本文・見出し・カスタムブロック内に「視点を表すラベルワード」を一切書かない**。視点は内容で示し、看板は出さない。

### 軸による例外（軸3＝記念日代行・サプライズ代行サービスのみ解禁・実績控えめ）

このルールは **軸1（記念日ギフト・サプライズ）・軸2（記念日デート・レストラン）では全面厳守**。ただし **軸3（記念日代行・サプライズ代行サービス）に限り、作り手＝Anniv側の立場を示す自己言及・看板ワードを「信頼の裏付け」として使ってよい**（例：「実際に依頼を受ける中で」「代行の相談を受けていて」）。軸3は代行サービスを検討している発注検討者向けで、作り手ならではの一次知見が E-E-A-T と差別化の芯になるため。

> **実績表現は控えめに（現時点の運用実態を反映）**：Annivはまだ実績が少ない立ち上げ期。「手がけてきた」「多数の実績」「〜社の実績」のような**実績の量・年数を暗示する表現は使わない**。代わりに「実際に依頼を受ける中で分かったこと」のように、量を主張せず個別の気づき・知見だけを根拠にする言い回しに留める。実績が積み上がったら、この節を実態に合わせて更新する。

**軸3で解禁されるのはここまで（歯止め）**：
- **乱用しない**：立場表明は導入・要点など記事の要所だけ。全H2に「代行会社として」を撒かない
- **自社を持ち上げない・煽らない**：8章の誇大・効能保証NGは全軸維持。「業界No.1」「唯一」等の自賛は禁止。立場は出しても優位性の自慢はしない
- **実績の量・年数を主張しない**：「多数の依頼実績」「創業以来〜件」のような数量誇示はNG（上記の実態に合わせる）
- **比較・ランキング記事では中立を保つ**：自社を比較対象に並べて持ち上げるのはNG（比較の物差しを渡す立場に徹する）。自社送客は従来どおりCTA（無料相談）で行う
- 「弊社」「当社」「Anniv」等の直接名乗りは、CTAや文脈上必要な箇所に限る（連発しない）

軸1・軸2では従来どおり、1個でも混入したらMust Fix。

### 完全NG（部分一致でも禁止）

- **「代行会社」を含む全表現**：「代行会社の視点」「代行会社視点」「代行会社目線」「代行会社として」「代行会社の立場」「代行会社が」など一切
- **主語化された自己言及**：「弊社」「自社」「我々」「私たち」「当社」「Anniv」「うちのチーム」
- **看板的な「〜の視点で」「〜の目線で」「〜の立場で」全般**：「プランナー視点で」「担当者の目線で」も同じ
- **属性ラベル型の枕詞**：「プロの目線で」「現場の視点で」
- **「運営側」「作り手」「中の人」を主語化する表現**

### 代わりにやること（視点は内容で示す）

- **切り口の中身そのものを書く**：「予算1万円台なら消耗品より形に残るものが響きやすい」「個室希望は予約の1〜2週間前が取りやすい目安」「サプライズは店側への事前連絡有無で成功率が変わる」など
- **事実ベースの実体験表現はOK**：「実際にプロデュースした案件で」「依頼を受けた中で」（顧客名・個人が特定される情報は伏せる）
- **「予算観点」「タイミング観点」「関係性観点」など切り口の名前を分析軸として提示するのは可**（属性ラベルではなく分析軸）

### 検出時の処理

1個でも本文・見出し・カスタムブロックに混入していたらMust Fix。事実・切り口の中身に書き換える。

## 3. 必須骨格（厳守）

### セクション内の骨格

**まずH2だけで書けるかを検討する**。下の「①H2のみ」の分量に収まり、内容が1つのまとまりとして自然に書けるなら、H3は作らずH2で完結させる。分量に収まらない、または明確に分けられる2つ以上のサブトピックがあって分割した方が自然なときだけ、H3で整理する。

**① H2のみのとき（H3なし）：** リード1〜3文 ＋ 装飾ブロック0〜2個 ＋ 締め0〜2文

```
## 見出し
[リード1〜3文：何の話か・結論。1文で済むなら1文]

[装飾ブロック0〜2個：表 / 箇条書き / :::info / :::box / 画像]

[締め0〜2文：判断軸や次への橋渡しが必要なときだけ。不要なら省略]
```

**② H3を使うとき：** H2直下に橋渡し1〜2文 ＋ 各H3が「リード1〜3文 ＋ 装飾ブロック0〜2個 ＋ 締め0〜2文」

```
## 見出し
[H2直下の橋渡し1〜2文：このH2で何を分けて説明するか]

### H3見出し
[リード1〜3文]

[装飾ブロック0〜2個]

[締め0〜2文]

### H3見出し
（同じ分量を繰り返す）
```

1つのH3がこの分量（1〜3文＋ブロック0〜2個＋0〜2文）を超えて膨らむなら、さらに分けるか別H2に切り出す。

### 厳守ルール

1. **見出し直下のテキストは1〜3文まで**（4文以上は冗長。続きは装飾ブロックに分散）
2. **1セクションの本文量の上限（厳守）**：ここでの字数は「そのセクションで読者が実際に読む本文の総量」の目安（リード・締め・装飾ブロック内のテキストも含む）。
   - **H2単体のとき（H3なし）**：そのH2配下は**400字以内**
   - **H3があるとき**：H2直下（橋渡し文）は**50字以内**に抑え、その下の**各H3が200字以内**
   - 超えそうなら、内容を最重要な論点に絞るか、H3で分割する／別H2に切り出す
3. **H3は必須ではない（H2のみで完結してよい）**：H2配下にH3を必ず置く必要はない。リード文＋装飾ブロック（表・箇条書き・カスタムブロック）で簡潔に述べられる章は、H3を無理に作らずH2だけで完結させる。**H3を入れるのは、(a) H2のみの分量（リード1〜3文＋ブロック0〜2個＋締め0〜2文）に収まらない、または (b) 明確に分けられる2つ以上のサブトピックがあって見出しで区切った方が読みやすい——このどちらかの場合のみ**
4. **H3を置く場合はH2直下にいきなり置かない**：H2とH3の間に1〜2文の橋渡し文を入れる
5. **見出し直後にいきなりカスタムブロックを置かない**： `:::info` `:::warning` `:::tip`の前に1〜3文挟む
6. **5文以上の長段落を作らない**
7. **同じ内容を本文と装飾ブロックで重複させない**：重複は装飾ブロック側を優先して本文を削る
8. **締め文は無理に書かない**：装飾ブロックで終わってよい
9. **1段落に「／」を3つ以上入れない**：詰め込み文は箇条書きに展開
10. **1つのH2/H3は「リード→ブロック→締め」の1パスで完結（往復禁止・最頻出の違反）**：ブロック→地の文→別ブロック→地の文…と交互に積み上げない。装飾ブロックは連続して0〜2個まとめて置き、その後ろの地の文は**締め0〜2文だけ**。ブロックの後にさらに新しい論点の段落を足したくなったら、それは別のH2/H3に切り出すサイン。**締めが3文以上・ブロックが3個以上・ブロックの前後や間に地の文を反復して挟む＝骨格違反**。出力前に各H2/H3で「リード何文／ブロック何個／締め何文」を実際に数える
11. **同じ主張を言い直さない（くどい繰り返しの禁止）**：1つのH2/H3の中で、リードで述べた結論を締めでもう一度言い換えただけの文を置かない。本文・表・箇条書きですでに示した内容を「つまり〜です」「〜で判断できます」と要約し直すのも重複。締めは新しい行動提言・次への橋渡しがあるときだけ置き、繰り返すだけなら削る（例：「利用できるのはTeamとEnterpriseに限られます」と書いた段落の末尾に「まずTeam/Enterpriseに加入しているかで判断できます」と再掲しない）

### 例外（必須骨格を適用しない場所）

- **リード文（記事冒頭、H2の前）**：3〜5行の課題共感型導入＋`:::summary` は通常通り
- **FAQセクション**：`:::faq` ブロック自体が装飾なので、見出し直下1〜3文＋ブロック＋締め0〜1文でよい
- **まとめH2**：振り返り文＋箇条書き＋締め（5章の専用ルール参照）
- **使い方STEP系**：操作手順は番号付きリストが本体。手順ブロック前後に1〜2行で囲む

## 4. 導入部と:::summary CTAブロック

### 4-1. 導入文（型A：課題共感型・デフォルト）

検索ユーザーが抱えている**複数の具体的な悩み**を冒頭で並列に並べ、「こうした疑問を抱える方は多いのではないでしょうか」「〜方は多いはずです」で締めて共感する。**導入はこのメディアの声（8-0章）が最も出る場所**。読者の迷いを一度受け止めてから、記事で何を整理したかを伝える。

**テンプレート：**
```
[記念日・シーン]で[メインKW]を探しているけれど、[悩み1]、[悩み2]、[悩み3]、[悩み4]――こうした疑問を抱える方は多いのではないでしょうか。

[このテーマで押さえるべきポイント1文]。本記事では[扱う論点1・論点2・論点3]を、[判断軸]として整理しました。
```

**記入例（軸1・彼女の誕生日プレゼント）：**
```
彼女の誕生日プレゼントを選びたいけれど、予算はいくらが普通なのか、付き合って1年目で重すぎないか、消耗品と形に残るものはどちらが喜ばれるのか――こうした疑問を抱える方は多いのではないでしょうか。

プレゼント選びで迷う原因は、相手の好みが分からないことよりも「判断の基準を決めていないこと」にあります。本記事では予算の相場、交際期間別の選び方、避けたほうがいいものを、選ぶ順番に沿って整理しました。
```

**書き方のルール：**
- 悩みは3〜4個を「、」で並列
- 各悩みは具体的な疑問形・口語（「〜できるのか」「〜は何か」「〜は誰が負うのか」など）
- 締めは「こうした疑問を抱える方は多いのではないでしょうか」「〜方は多いはずです」で共感
- 2段落目の最後に語りかけを1文足してよい（「まずは予算から一緒に整理していきましょう」）。定型の締め（「ぜひ参考にしてください」）はNG
- 2段落目で「本記事では◯◯を整理します」で扱う内容を宣言
- 「重すぎないか」「センスがないと思われないか」「当日までに間に合うか」など、**読者が実際に頭の中で言っている言葉**を入れる（不安の言語化＝共感。ただしポエム・感情の押し売りはNG＝8章）
- **冒頭100字以内にメインKWを自然に含める**（SEO要件）
- 「この記事を読むとわかること」ボックスは使わない
- 導入は2〜3文で完結

### 4-2. 型B（時事事実型）

「〇年〇月、〇〇が〇〇になりました」→ 機能・背景の説明へ。最新ニュース・新サービス・新モデル系で使う。



### 4-3. `:::summary` CTAブロック（必須）

導入文の最後に、記事全体の**結論**を要約した`:::summary`ブロックを必ず置く。

**ルール：**
- **箇条書きのみで構成**（冒頭にリード文・説明テキストを入れない）
- **「何を扱うか」ではなく「結論」を書く**：「〜を比較します」NG、「無料で商用利用できるのはAとBの2つ」OK
- そのブロック単体で記事のポイントが分かる粒度
- メインKW・サジェストKWを自然に含める
- 箇条書き3〜5項目（各15〜30字程度）
- 断定形（「〜と言えそうです」ではなく「〜が最適です」）

**例：**
```
:::summary
- 予算1万円台なら消耗品より形に残るものが好印象
- シーン別の最適解：3年目以降はアクセサリー、初めての記念日は手紙＋花が定番
- 注意点：相手の趣味を知らないまま高額品を選ぶと失敗しやすい
:::
```

## 5. まとめH2（必須・最後に必ず置く）

**まとめH2を置かずに記事を終わらせない**。FAQセクションの後に、結論を含む見出しのまとめH2を必ず配置する。

### 必須構造

1. **見出しは結論を含める**：「まとめ：◯◯で◯◯できる」「まとめ｜◯◯する前に確認したいこと」「◯◯は誰におすすめか」など。「まとめ」単体はNG
2. **振り返り文1〜2文**：記事の主旨を1〜2文で再確認
3. **要点の箇条書き3〜5項目**：`:::box color=#1a2840 label="この記事の要点"` のラベルボックスに記事の最重要ポイントを3〜5項目でまとめる（**この「要点」パターンに統一**。）
4. **行動提言1〜2文**：「まずは予算を決めてから候補を3つに絞る」「予約は1か月前を目安に押さえる」など、読者がその日にできる具体的な次のアクション。指示口調（「〜してください」）ではなく提案型（「〜しておくと安心です」）で書く（8章）
5. **時制と一次情報の再明示**：「執筆時点（YYYY年MM月）の情報です。最新は[公式](URL)を確認してください」を最後に添える

### テンプレート

```
## まとめ｜◯◯は◯◯（結論を含む見出し）

[振り返り文1〜2文：記事の主旨を再確認]

:::box color=#1a2840 label="この記事の要点"
- ◯◯（記事の最重要ポイント）
- ◯◯
- ◯◯
:::

[行動提言1〜2文：次のアクション・一次情報確認の促し]

本記事は◯年◯月時点の情報です。最新は[公式](URL)を確認してください。
```

### NGパターン

- まとめH2を置かずFAQで記事を終える
- 見出しが「まとめ」だけで結論を含まない
- 振り返り文だけで箇条書き・行動提言がない
- **要点ボックス以外の構成にする**
- 「いかがでしたか」「最後まで読んでいただきありがとうございました」を入れる

## 6. タイトル

**大原則：タイトルは「人がクリックしたくなるフック」が主役。SEOのKWはその自然文に溶かす（従）。KWを並べただけのタイトルは作らない。** サジェスト・関連KWを詰め込むほどSEOに効く、ではない。単語を「｜」や「・」で羅列しただけのタイトル（例：「〇〇比較｜A・B・無料・2026」）は、検索結果で機械的に見えてCTRを落とす。読者の本音の疑問・意外な事実・具体的な数や対象で興味を引き、その文の中にメインKW＋関連KWを1〜2個だけ自然に含める——この両立を狙う。KWカバレッジはH2見出し側でも稼げるので、タイトルで全部背負わない。

- **32字以内**（PC全角32字・モバイル40字程度で省略表示）
- **メインKWを前半（左寄せ）に自然に入れる**（完全一致が理想だが、語順が不自然になるなら助詞を足して自然文にする）
- **関連KWは"自然文に溶かして"1〜2個まで**：リサーチのサジェスト・関連KW・共起語から、そのタイトルの文意に馴染むものだけを選ぶ。**3個以上を記号（｜・/）区切りで並べない（＝羅列でNG）**
- **フックを必ず1つ入れる（いずれかの型）**：①読者の本音の疑問を投げる（「〇〇って結局どれ？」「〇〇は重い？」）／②意外な事実・前提のズレを示す（「実は〜なのは少ない」「値段より効くのは〇〇」）／③具体的な数・タイプで整理感（「4タイプで選ぶ」「7選」）／④対象読者を名指す（「付き合って1年目の人へ」）
- **CTR訴求要素を1つ以上**：数字（「7選」「4タイプ」）／年号（「2026年」「最新」）／【タグ】（「【無料】」）。記号の多用（！？★）はしない
- **やらないこと**：効能保証（「失敗しない」「迷わない」＝8章NG）／リスク比喩（「地雷」等＝8章NG）／中身の薄い紋切り型（「徹底解説」「完全網羅」「大公開」だけで具体を示さない語で釣る）／ポエム調（「大切な人へ贈る特別なひととき」＝8章NG。本文と同じ声で書く）
- **毎回この4つのフック型を各1案ずつ、計4案を提示する（固定運用）**：①疑問型（「〜って結局どれ？」）②意外性型（「〜より効くのは〜」）③整理型（「〜は4タイプ｜…」）④名指し型（「〜な人へ｜…」）。記事ごとに映えるフックが違うので、型を揃えて出しユーザーに選ばせる。全案が同じ単語の並べ替えにならないように

NG例：
- 「彼女の誕生日プレゼントについて完全解説！おすすめを紹介します」（メインKWだけ・紋切り型・フックなし）
- 「誕生日プレゼント比較｜彼女・予算別・おすすめ・2026」（単語を記号で羅列しただけ・人が読む文になっていない）
OK例：
- 「彼女の誕生日プレゼント、結局何が喜ばれる？予算別7選」（疑問フック＋「予算別」＋数字）
- 「1万円以下で選べる誕生日プレゼントは実は少ない｜2026年版7選」（意外性フック＋「予算」＋年号＋数字）

## 7. 見出し（H2/H3）

### 基本ルール

- H2：体言止め or「〜する方法」が基本
- H3：体言止め or「〜する」「〜できる」連体形
- 数字を入れる：「4つのメリット」「14選」「3つの注意点」
- タグ付き：「【開発者向け】〜」「【完全無料】〜」「【おすすめ】〜」
- まとめ見出しには結論を含める

### SEO最適化ルール（必須）

1. **見出しは25〜30字以内**（できれば25字以内）
2. **メインKW or サジェストKW or 共起語を必ず含める**
3. **KWは見出しの前半に配置**（左寄せ）
4. **各H2に異なるサジェストKWを分散**（1記事内でKW露出を最大化）
5. **冗長な説明・装飾を削る**：「〜という観点で」「〜について解説」「〜を踏まえた上で」「〜を軸に厳選」などはNG
6. **H2の数は5〜7個を絶対遵守**（総合ガイド記事のみ8個以上可。それ以外は5〜7個から1個もはみ出さない）

### H2が多くなった時の統合手順（最重要）

執筆時・レビュー時にH2が8個以上になりがち。**多くなる傾向を前提に必ず統合する**。手順：

1. **似たトピックを1つに統合**：「メリット」「デメリット」→「メリット・デメリット」、「料金」「プラン比較」→「料金プラン」
2. **小粒なトピックはH3に降格**：単体でH2にする必要がないものは親H2配下のH3に
3. **重複・冗長なH2を削除**：同じ内容を別の角度で書いているものは1つにまとめる
4. **「導入的なH2」を削る**：「○○とは」が冒頭にあって、その後の章で十分説明される場合はリード文に吸収
5. **網羅性より優先順位**：全部書こうとせず、検索意図に対して最重要な5〜7軸に絞る

8個以上を「総合ガイド記事だから仕方ない」と妥協しない。**総合ガイド記事と明示的に定義されていない限り5〜7個に収める**。

### サジェストKW分散の例

メインKW「彼女 誕生日プレゼント」の場合：
- H2-1：「彼女 誕生日プレゼント 予算」を含む
- H2-2：「彼女 誕生日プレゼント 選び方」を含む
- H2-3：「彼女 誕生日プレゼント 年代別」を含む
- H2-4：「彼女 誕生日プレゼント おすすめ」を含む
- H2-5：「彼女 誕生日プレゼント 注意点」を含む

## 8. 文体・口調

> **軸による寄せ（共通ルールの上に重ねる）**：この章のルールは全軸共通の土台。コンテンツ軸ごとの「文体の寄せ」は `content-axis.md`（SSOT）で定義し、その範囲だけ調整する（例：記念日代行・サプライズ代行サービス軸は作り手の立場を信頼の裏付けとして一部許容）。ただし**誇大・煽り・効能保証・リスクの比喩煽り（下記「避ける汎用表現」）はどの軸でもNG**で、軸の寄せはこれを上書きしない。

### 8-0. メディアの声（全記事共通・最初に決める）

**書き手は「記念日のプランを一緒に考えている人」**。友人から「彼女の誕生日、何あげたらいいと思う？」と相談されて、知っていることと調べたことをもとに落ち着いて答えている——その声で書く。評論家でもコンサルでも先生でもない。

| 観点 | このメディアの立ち位置 |
|---|---|
| 立場 | 上から教える人ではなく、隣に座って一緒に考える人 |
| 距離感 | 親しみやすいが馴れ馴れしくない。「です・ます」は崩さない |
| 温度 | 読者の迷い・焦り・不安をいったん受け止めてから、判断材料を出す |
| 芯 | 気持ちに寄り添っても、事実と判断軸は曖昧にしない（優しさ＝断定を避けること、ではない） |

**判定は1文ずつ「これを友人に口で言うか？」**で行う。口で言わない硬さ（事務的・翻訳調・レポート調）も、口で言わない軽さ（タメ口・煽り・馴れ馴れしさ）も、どちらもNG。

**寄り添いと断定は両立させる**。気持ちの話（迷い・不安・関係性）は柔らかく受け止め、事実・相場・判断軸は言い切る。順序は「受け止め→事実」。逆にすると冷たく読める。

**共感と呼びかけは積極的に使う**。「迷いますよね」と受け止める、「あなたの場合は」と語りかける、「思い出してみてください」と問いかける——相談に答えている声なので、これらがあるのが自然な状態。制限するのは**同じ言い回しの反復**と**中身のない感情表現（ポエム・押し売り）**だけ（8-1・8-2・8-5章）。

- OK：「何を贈っても喜んでくれる相手ほど、かえって決め手がなくて悩みます。予算1万円台なら、消耗品より形に残るものを選ぶと満足度が上がりやすいです」
- NG（冷たい）：「予算1万円台では形に残るものが合理的です」
- NG（ふわふわ）：「気持ちが伝わればどんなものでも喜んでもらえるはずです」

### 8-1. 基本原則

- 「です・ます」調で統一・人間が書いたように自然な日本語
- **1文は短く・一文一義**：40字前後を目安に（最長でも60字）。1文に論点を2つ以上詰めない。「〜が」「〜ため」「〜ので」「〜が、」で節を連結して長くしない——いったん句点で切って2文に分ける
- 1段落：2〜4文（5文以上は分割対象）
- 同じ語尾を3文連続させない（「〜です」「〜ます」「〜となります」「体言止め」を混ぜる）
- 主語と述語の距離を近くする
- 具体的な数値・固有名詞・引用を入れる（「多くの人が〜」より「20代女性の平均予算は1万〜1万5000円」）
- 推測は「〜と推測されます」「〜の可能性があります」と明示
- **呼びかけはあり**：二人称「あなた」を使ってよい。「〜の方は」「〜してみてください」「一緒に見ていきましょう」のように読者へ直接語りかける形も可。相談に答えている声なので、語りかけがあるほうが自然（8-0章）
- ただし**日本語は主語を省くほうが自然**：「あなた」を毎文に入れると翻訳調になる。呼びかけを強めたい箇所（導入・各H2のリード・まとめ）で使い、それ以外は主語を省く（「迷ったときは」「予算が1万円なら」）。「〜の方は」も全文にはかぶせない
- **共感の一文を入れる**：「迷いますよね」「悩むところです」のように読者の気持ちを受け止める文を、導入と各H2のリードで自然に使う。ただし**同じ言い回しの反復はしない**（8-5章）
- 推奨は**提案・お誘い型で書く**：「〜することをおすすめします」「〜が喜ばれやすいです」「〜してみてください」「〜から決めていきましょう」。「〜すべきです」「〜しなければなりません」など命令・義務の言い方はしない
- **絵文字・顔文字・「！」の多用はしない**（「！」は記事全体で0〜1回）

### 8-2. 寄り添いを作る4つの型（これ以外の方法で温度を出そうとしない）

温度は形容詞や感嘆で出すものではなく、**書く順番と具体性**で出す。

1. **状況を先に言語化する**：読者が置かれている状況を1文で言い当ててから本題に入る（「渡す前日になっても、これで合っているのか不安になります」）
2. **迷いを否定しない**：「悩んで当然」の前提で書く。「〜で悩む必要はありません」より「悩むポイントはだいたいこの3つに集約されます」
3. **失敗を責めない**：注意点は読者の落ち度ではなく「よくあること」として書く（「サイズが分からないまま指輪を選ぶと外れやすい」＝事実として）
4. **相手（贈られる側）の気持ちに触れる**：「なぜそれが喜ばれるのか」を一言添える。モノの説明で終わらせない
5. **呼びかけて一緒に考える**：判断を投げっぱなしにせず、読者に問いかけてから答えを出す（「相手が普段どんなものを身につけているか、思い出してみてください。そこから絞ると外しにくくなります」）

**共感・呼びかけの量に上限は設けない**。相談に答えている声なので、読者の気持ちに触れる文は各セクションにあってよい。

**やってはいけない寄り添いの偽装**：読者の性格・経験・感情を決めつける投影（「〜してきた方ほど、〜と感じるはずです」）、感情の押し売り（「大切な人のために、心を込めて」）、**同じ共感フレーズのコピペ反復**（「〜ですよね」を全セクションの頭に置く等＝8-5章）。共感は毎回違う言い方で、その場の内容に沿って書く。

### 8-3. 硬い・冷たい表現の書き換え（このメディア特有のNG）

技術メディア調の言い回しが混ざると一気に温度が下がる。以下は見つけたら書き換える。

| 硬い・冷たい | 書き換え |
|---|---|
| 「予算1万円台では形に残るものが合理的です」 | 「予算1万円台なら、形に残るものを選ぶと満足度が上がりやすいです」 |
| 「以下の3つの要件を満たすことが推奨されます」 | 「選ぶときは、次の3つを見ておくと外しにくいです」 |
| 「本項では店選びの条件を整理する」 | 「店選びで先に決めておきたい条件は3つです」 |
| 「当該サービスの利用を検討する際は」 | 「頼むかどうか迷っているなら」 |
| 「最適解はアクセサリーである」 | 「アクセサリーが選ばれやすいのは、日常的に身につけられるからです」 |
| 「〜が求められます」「〜が必要とされます」 | 「〜しておくと安心です」「〜は早めに決めておきます」 |
| 「上記の通り」「前述のように」 | 削除するか「さきほどの3つの条件で言うと」 |
| 「〜のケースにおいては」 | 「〜のときは」 |
| 「ユーザー」「当該」「〜の観点から」 | 「贈る側」「その」「〜で見ると」 |

**呼び方の統一**：読者は「贈る側」、相手は「相手」「パートナー」「恋人」。KWに合わせて「彼女」「彼氏」を使うのは可。「ユーザー」「当事者」「男性諸君」は使わない。

**「丸投げ」は使わない（記事本文・見出し・SNS・LP のすべて）**：頼む側を「面倒だから投げた人」に見せる語で、記念日に手をかけたい読者の実像と合わない。プランナーが一緒に決めていくというサービスの中身とも矛盾する。同じ意味は次で言う。

| 使わない | 言い換え |
|---|---|
| 丸投げできる／丸投げしたい | **まるごと任せられる**／お任せいただけます |
| 丸投げ先 | 準備を代わりに進めるところ |
| 判断を丸投げする（書き方の話） | 判断を投げっぱなしにする |

読者の検索語に「丸投げ」が含まれる場合の扱いは、KWごとにオーケストレーターがユーザーへ確認する（勝手に本文へ持ち込まない）。

### 8-4. AI臭NGパターン（名指しで潰す）

| AI臭パターン | NG例 | 書き換え |
|---|---|---|
| 疑似本音語の連発 | 「価格が高めなのが正直なところです」 | 「価格は高め。相場1万円台に対し3万円〜と2倍ほどします」 |
| 「〜と言って良いです」 | 「記念日の定番と言って良いです」 | 「記念日の定番」 |
| 「〜が現実解／現実的／選択肢」連発 | 「併用が現実解です」 | 1記事で1〜2回まで。「〜にする」「〜を選ぶ」と動詞で言い切る |
| 読者投影 | 「これまで悩んできた方ほど、〜と感じるはずです」 | 削除するか事実だけ残す |
| スラッシュ詰め込み長文 | 「条件：個室／夜景／記念日プラン」 | 箇条書きに展開。1文に「／」を3つ以上入れない |
| 「〜まで踏み込む」 | 「予約観点・演出観点まで踏み込む」 | 「予約のコツや演出の頼み方も扱います」 |
| 体感ふわっと数値 | 「体感で1.5倍ほど喜ばれます」 | 削除or実数で。「体感」「ほど」「くらい」を数値とセットで使わない |
| 「〜のレンジです」 | 「1万〜3万円のレンジです」 | 「1万〜3万円が中心です」 |
| 「期待値調整に使ってください」「〜の目安です」 | 削除。読者に指示する代わりに事実を書く |
| 「〜が、〜のが、〜のも」連結 | 「〜が〜のが正直なところです」 | 短い文に切る |
| 「〜ことを忘れずに〜してください」 | 「忘れずに予約してください」 | 「予約は1か月前を目安に入れておきます」 |

### 8-5. 構造的なAI臭

- **「〜のは事実です」「〜のも事実です」「〜のも確か」**：1記事で2回以上使わない
- **「特に〜は〜」「とくに〜」**：強調が過剰。1記事で2回まで（1セクション内は1回まで）
- **「〜してみて見えた」「〜してみた実感」「〜してみてわかった」**：体験談ぽさ偽装。1記事で1回まで
- **「が」「ため」「ので」で節を長く繋ぐ複文**：「〜が、〜が」「〜ため〜、〜ため〜」など。1文に逆接・理由を2つ以上重ねず、句点で切って短い文に分ける
- **箇条書きの末尾が全部同じ語尾**：「〜できる」3連続NG
- **同じ単語を1段落で繰り返さない**：「気持ち」「特別」「記念日」など便利語ほど偏る
- **共感フレーズの型化**：共感・呼びかけ自体は積極的に使ってよいが、**同じ表現の反復はNG**。「〜ですよね」「〜のではないでしょうか」「〜という方も多いはずです」は**同一表現が1記事2回まで**。3回目からは別の言い方に変える（「迷うところです」「決めきれないまま当日が近づきます」「気になりますよね」など）。全H2のリードが同じ形で始まるのもNG

### 8-6. 避ける汎用表現

- 「〜していきます」「〜となっています」の多用（**読者を誘う「〜していきましょう」「〜してみてください」は可**。NGなのは意味のない進行形と、中身のない定型の呼びかけ）
- 「〜についてご紹介します」「〜について解説していきます」の無意味な前置き
- 「いかがでしたか」「ぜひお試しください」「最後まで読んでいただきありがとうございました」
- 「〜することができます」（「〜できます」に短縮）
- 「素晴らしい」「画期的な」「圧倒的な」のような根拠のない強調語
- 「〜と言われています」「〜とされています」の多用
- **感情の押し売り・ポエム**：「大切な人のために」「心を込めて」「一生の思い出に」「かけがえのない時間」「特別な一日を演出しましょう」など。気持ちは形容詞で盛らず、具体的な行動・事実で伝える（例：「一生の思い出になるサプライズを」→「当日の流れを先に決めておくと、渡すタイミングで慌てずに済みます」）
- **読者に効能・結果を保証する言い回し**：「〜すると迷いません」「〜すれば失敗しません」「〜で迷わない」「〜すれば安心です」「絶対に喜ばれます」など。枠組み・比較軸・基準を提示するときは、読者の体験を約束せず**書き手が整理した事実**として書く（例：「次の5つの軸で見ると迷いません」→「以下の5つの基準で整理しました」）
- **リスクを比喩で煽る表現**：「地雷」「踏みやすい地雷」「落とし穴」「罠」「ハマる」「沼」など。注意喚起は比喩で煽らず「注意点」「気をつけたい点」「見落としやすい点」と事実ベースで書く（例：「彼女へのプレゼントで踏みやすい地雷」→「プレゼント選びで見落としやすい注意点」）
- **不安を煽って動かす書き方**：「今すぐ動かないと間に合いません」「これを知らないと後悔します」。期限・締切は事実として書く（「人気店の記念日プランは1〜2か月前で埋まります」）
- **「先に結論を言うと」「結論から言うと」式の前置き**：もったいぶった定型句。結論は前置きなしでそのまま書く（例：「先に結論を言うと、一部の項目で上回ります」→「一部の項目で上回りますが、〜」）
- **抽象名詞＋「〜になります」式の翻訳調の締め**：「〜の出発点になります」「〜の起点になります」「〜の第一歩になります」など。説明くさく中身が薄い。具体的な事実・行動で言い切るか、締めごと削る（例：「店選びの出発点になります」→「まず個室があるかどうかで候補が絞れます」または削除）

### 8-7. 書き直しの基本姿勢

- **事実は断定・気持ちは受け止め**：相場・条件・段取りは「〜します」「〜が向いています」と言い切る。読者の迷いに触れる部分だけ柔らかくする。全文を断定で埋めると冷たく、全文を柔らかくすると中身が消える
- **数値・固有名詞は残し、修辞語は削る**：「1万〜1万5000円」「予約は1か月前」は残す、「正直」「体感」「素敵な」は削る
- **呼びかけは残す・命令は削る**：「〜してみてください」「〜から決めていきましょう」は残してよい。削るのは義務・命令調（「〜すべきです」「必ず〜してください」）と、中身のない呼びかけ（「ぜひ検討してみてください」）
- **温度が足りないと感じたら、形容詞ではなく具体を足す**：「素敵なサプライズ」ではなく「渡す前にお店へ電話でデザートプレートを頼んでおく」

## 9. 装飾要素（使用できるマークダウンのみ）

| 要素 | 記法 | 使う場面 |
|---|---|---|
| 強調 | `**強調**` | 重要ワード・比較軸ラベル・強調したい結論文 |
| 斜体 | `*斜体*` | 補助的な強調・固有表現 |
| 見出し | `##` `###` | H2 / H3 |
| 箇条書き | `-` | メリット列挙・手順概要・注意点リスト・まとめ要点 |
| 番号付きリスト | `1.` | STEP・順序のある手順 |
| 引用 | `>` | 公式情報・第三者発言の引用 |
| リンク | `[テキスト](https://)` | 外部参照・内部リンク |
| コードブロック | ` ``` ` | コード・コマンド |
| インラインコード | `` `code` `` | コマンド名・キー・短い識別子 |
| 表 | `\| 項目 \| 説明 \|` | プラン比較・ツール比較 |
| info ブロック | `:::info` … `:::` | 補足情報 |
| warning ブロック | `:::warning` … `:::` | 注意点 |
| danger ブロック | `:::danger` … `:::` | 危険・誤情報の警告 |
| tip ブロック | `:::tip` … `:::` | ヒントやコツ |
| summary ブロック | `:::summary` … `:::` | 結論・ポイントの要約（箇条書き内包） |
| faq ブロック | `:::faq` … `:::` | FAQ（Q. / A. 形式） |
| timeline ブロック | `:::timeline title=〇〇` … `:::`（中に `### 見出し`。STEP番号は表示側が自動付与するので見出しに「STEP1：」等を書かない） | 操作手順・導入ステップ・時系列の流れ |
| 目次 | `[[toc]]` | 見出しから目次を自動生成（記法はこれのみ） |
| マーカー | `==テキスト==`（標準）/ `==g:テキスト==`（緑）/ `==p:テキスト==`（ピンク） | 本文中の語句を蛍光ペン的にハイライト |
| 画像プレースホルダー | `[画像：〇〇]` | 画像を入れたい位置と内容（実画像は後で差し込み） |
| ラベルボックス | `:::box color=#XXXXXX label="〇〇"` … `:::` | 小さなまとまり（メリット・デメリット・注意点等） |
| カラム | `::::columns cols=2` ＋ `:::col` … `:::` ＋ `::::`（**外側は4コロン**） | 2〜3列の並置（比較・対になる説明） |
| 送客バナー | `:::banner theme=navy label="〇〇" href="https://…"` … `:::` | 記事内の任意の位置に置く送客導線（文字だけ・細い） |
| ビジュアルCTA | `:::hero title="〇〇"` … `:::` | 写真を敷いた強い送客導線（1記事に1本まで） |
| 折りたたみ | `:::details title=〇〇` … `:::` | 長い補足を畳む（FAQとは用途が違う） |
| 【タグ】 | 見出し冒頭の `【】` | 対象読者を見出し冒頭に明示 |

**`---`（水平線）は使わない**：段落の区切りは見出し・直下文・カスタムブロックで作る。

**閉じの `:::` は必ず単独行に置く**：`… 決める :::` のように本文の末尾へ付けない。付けるとブロックが閉じず、以降の記事が丸ごとその中に入る（レンダラー側で救済してはいるが、原稿は正しい形で書く）。閉じ忘れは公開前チェックが×で拾う。

**ブロックの中身も普通のMarkdownとして書く**：箇条書きにしたい行は `- ` で始める。素の行を並べても1つの段落に畳まれるだけで、箇条書きにはならない（`:::summary` は 4-3 のとおり箇条書きのみ）。

**装飾は積極的に使う**：プレーンテキストの長段落を避け、表・箇条書き・ラベルボックス・画像・カスタムブロックで視覚的に整理する。

**ブロック内の文章は1〜2文で簡潔に**：`:::info` `:::warning` `:::danger` `:::tip` などカスタムブロックの中身は、要点を1〜2文（または短い箇条書き）でまとめる。長い説明をブロックに詰め込まない。補足が長くなる場合はブロックの外に本文として書き、ブロックには結論・注意点のコアだけ残す。**ラベルボックス（`:::box`）はこのルールの対象外**（箇条書きでまとまった情報を入れる用途のため）。

### 画像プレースホルダー

- 記法：`[画像：〇〇のスクリーンショット | alt: 〇〇のKWを含むaltテキスト]`
- altテキストはメインKWまたは関連語を自然に含める（KW詰め込みNG）
- altは画像の内容を客観的に説明（推測・主観は避ける）
- 入れる場面：ツール紹介のH2直下／操作手順のSTEPごと／生成結果・比較サンプル／料金プラン表
- **プレースホルダーの差し替え先**：写真でよければ `素材/`（CC0のフリー素材ライブラリ。一覧は `素材/一覧.md`）から選ぶ。ホテル・レストラン・ギフト・花・ケーキ・キャンドル・カップル（顔なし）・夜景がある。合うものが無ければプレースホルダーのまま残し、公開時に判断する
- **写真はイメージ**。料金・比較・手順など情報そのものは表・箇条書き・要約カードで見せる（写真で情報の代わりをしない）

例：`[画像：〇〇（商品/サービス名）の料金プラン画面 | alt: 〇〇 プラン別の料金比較]`

### ラベルボックス

- 記法：
  ```
  :::box color=#1a2840 label="ラベル名"
  本文をここに（箇条書き・短文どちらもOK）
  :::
  ```
- `color` はHEXで指定。記事の文脈に応じて選択（参考：記事の要点・まとめ系=`#1a2840`紺〈Annivのブランド主色。迷ったらこれ〉 / 注意・デメリット系=`#e74c3c`赤 / 補足・情報系=`#3498db`青）。**緑は `:::tip` ブロックが持っているので `:::box` では使わない**
- よく使う `label` 名：`メリット` / `デメリット` / `注意点` / `ポイント` / `こんな人におすすめ` / `料金まとめ` / `使ってみた感想`
- 積極的に使う：長い説明文よりラベルでまとめる方が読みやすく、AIO引用にも有利

### カラム（2〜3分割）

```
::::columns cols=2
:::col
左の内容
:::
:::col
右の内容
:::
::::
```

- **外側は必ず4コロン（`::::`）**。3コロンで書くと最初の `:::` が外側を閉じてしまい崩れる
- `cols` は `2` か `3`。それ以外・未指定はすべて2列になる
- 900px以下では1カラムに落ちる。`:::col` の数が `cols` と合わなくても折り返すだけで壊れない
- **`:::col` の中に `:::` で始まるブロック（`:::box` `:::info` 等）を入れると崩れる。** `columns` が4コロン・`col` が3コロンなので、内側の `:::` が先に `col` を閉じてしまう。カラムの中身は**文章・箇条書き・表・画像まで**に留める

### 送客バナー

```
:::banner theme=navy label="記念日の準備をまるごと任せる" href="https://anniv.gift/contact"
補足の1行（省略可）
:::
```

- `theme`：`navy`（既定）／ `gold`（控えめ）／ `line`（LINE緑）。不正値は navy
- `href` は `https://` か `/` 始まりのみ有効。省略時は問い合わせフォーム（`theme=line` のときはLINE）
- クリック計測は自動で入る（`data-cta` は遷移先で決まる。`event_label` は `article_banner`）
- **バナー本文中にリンクを書かない**（バナー全体がリンクなので入れ子になって壊れる）
- 軸3の固定CTA（`:::box label="無料相談・お問い合わせ"`）とは別物。**1記事に何本も置かない**

### ビジュアルCTA（写真つき）

```
:::hero title="記念日の準備、まずは相談してみる"
プレゼント選びからお店の予約、当日の演出まで。予算が固まっていない段階でも相談できます。
:::
```

- **これだけで出る**（写真・ラベル・ボタン文言・リンク先はすべて既定値）。変えたいときだけ属性を足す
- 属性：`title`（見出し。既定「記念日の準備、まずは相談してみる」）／ `label`（上の小さい文字。既定「無料相談・お問い合わせ」）／ `btn`（ボタン文言。既定「無料で相談する」）／ `href`（既定は問い合わせフォーム）／ `image`（既定 `/assets/cta-hero.webp`）
- **文言は「任せる」より「相談してみる」寄りに**。いきなり全部任せる決断を迫るより、まず相談という一歩の方が心理的な段差が低い
- **文字は画像に焼き込まない**。写真は背景の装飾（`alt=""`）で、見出し・補足・ボタンはHTMLで出る。だから写真を差し替えても文言は生きるし、モバイルで文字が潰れない
- 本文は補足の1行（省略可）。**中にリンクを書かない**（全体がリンクなので入れ子で壊れる）
- クリック計測は自動（`event_label` は `article_hero`）
- **1記事に1本まで**。`:::banner`（文字だけの細い導線）と同じ記事に何本も並べない。使い分けは「本文の途中で軽く触れる＝`:::banner`／ここで決めさせたい＝`:::hero`」
- 置き場所は料金・依頼の流れ・サービスの選び方など**検討の温度が上がった直後**。導入直後や結論前に置かない
- **軸3の固定CTA（`:::box label="無料相談・お問い合わせ"`）と同じ記事に併用しない**。軸3はあちらが本命なので、`:::hero` は軸1・軸2の記事で使う

### 折りたたみ

```
:::details title=補足：予算の内訳
中身
:::
```

- `title` 省略時は「詳しく見る」
- 中の見出しは目次に載らない（閉じた状態が既定なので飛んでも見えないため）
- 一問一答は `:::faq`、長い補足は `:::details` と使い分ける

### カスタムブロックの記法例

```
:::summary
- 結論を一行で
- ポイント1
- ポイント2
:::

:::faq
Q. 質問1

A. 回答2

:::timeline title=作業手順
### 最初の手順のタイトル
1番目の本文をここに記述します（見出しに「STEP1：」は書かない。表示側が自動でSTEP番号を振る）。

### 次の手順のタイトル
2番目の本文をここに記述します。

```

### 目次（`[[toc]]`）

- 記法は `[[toc]]` のみ。記事内の見出しから目次が**自動生成**される（手書きで項目を並べない）。
- 置く場所：導入文（＋`:::summary`）の直後、最初のH2の前。長尺記事で回遊性を上げたい時に置く。

### マーカー（蛍光ペン）

- 記法：`==テキスト==`（標準）／ `==g:テキスト==`（緑）／ `==p:テキスト==`（ピンク）
- 色の使い分け（目安）：標準＝一般的なスポット強調／ 緑＝ポジティブ・おすすめ・結論／ ピンク＝注意・要チェック・差別化ポイント
- **`**強調**`（太字）との使い分け**：太字は結論文・比較軸ラベルなど構造的な強調。マーカーは本文を読み流す中で目を留めさせたい「数値・キーワード・差別化ポイント」のスポット強調。
- **H2ごとに1箇所だけ置く（必須）**：1つのH2セクション全体で蛍光ペンは1箇所のみ。配下にH3がある場合は、そのH2の中で最も要点となるH3を1つ選び、その本文（箇条書き・ラベルボックス内など、どこでもよい）の数値・キーワード・差別化ポイントを1語マーカーする。全H3に置かない——重要度で1つに絞る。H3がないH2は本文内に1箇所。まとめH2は振り返り文に置く。マーカーすべき語が見当たらないH2は要点が立っていないサインなので、本文側を見直す。
- **乱用しない**：H2ごとに1箇所が上限（2箇所以上はNG）。多用すると強調が効かなくなる。太字とマーカーを同じ語に重ねがけしない。

### 要約カード（H3群を1枚の画像にまとめたもの）

H2配下のH3を1枚のカード画像に圧縮して、見出し直下に置く装飾。読者がそのセクションで何が分かるかを1秒で掴めるようにするためのもの。

- **対象は「H3が2個以上あるH2」だけ**。H3が0〜1個のH2には作らない。**カードを出したいからH3を増やすのは禁止**（H3の粒度ルールは3章が優先）
- **生成はオーケストレーター（anniv-write-article Step 6-2）が `/anniv-card` スキルで行う**。writer・reviewerは作らない（Bashを持たないため）。writerは本文だけ書く
- **置き場所は該当H2の見出し直下**（H2の次の行・リード文より前）。画像→リード文→H3の順。**3章「見出し直後にブロックを直置きしない」の唯一の例外**がこのカード
- **altは必須**：メインKWまたは関連語を自然に含める（`![彼女の誕生日プレゼント 予算と選び方の要点](images/card_01_budget.webp)`）
- **重複を作らない**：カードを置いたH2の中に、H3の内容をそのままなぞる要約ボックス・要約表を別途置かない
- **カード内の文言も8章の文体ルールに従う**：タイトル10字以内・説明15字以内で、煽り・ポエム・効能保証は使わない（「絶対喜ばれる」「一生の思い出」はNG）
- **色はブランド固定**（ネイビー×ゴールド×淡いブルー）。記事ごとに色を変えない。配色を変えるときは `.claude/scripts/card-renderer/template.html` の `:root` を直す（`src/styles/tokens.css` と同じ値）
- **画像はWebPで入れる**（PNGのままだと1枚500〜700KBでLCPが落ちる。変換は anniv-write-article Step 6-2）
- **公開時はR2にアップロードしてURLを差し替える**：ローカルの `![alt](images/card_XX_xxx.webp)` のままでは公開サイトに出ない。管理画面の「画像をアップロード」で `![alt](/media/img/<key>)` に置き換える（anniv-write-article Step 6-7）

## 11. インラインリンク

### 外部リンク（一次情報の引用）

- **アンカーテキストは本文中のサービス名・機能名・固有名詞**
- **「公式ページはこちら」「詳細はこちら」のような誘導文NG**
- **同一URLへのリンクは記事内で初出時のみ**
- **リンク対象**：店舗・施設の公式サイト・公式予約ページ・自治体/観光協会等の公的情報・信頼できるメディアの一次情報
- **使わない**：SNS投稿・個人ブログ・まとめ記事への外部リンク

NG：「予約はこちら」
OK：「東京タワー近くの [〇〇レストラン](URL) は〜」

### 内部リンク（同サイト内の関連記事）

- **内部リンクは独立した段落として差し込む**：直前で段落を分け、関連記事を案内する一文を1つ置く。本文の途中にインラインで混ぜない
- **型**：「また、◯◯については、『記事タイトル』で解説していますのでぜひお読みください。」。◯◯にリンク先記事のテーマ（メインKW・関連語）を入れ、**アンカーはリンク先の記事タイトルに張る**（「こちら」「詳細はこちら」のような内容のないアンカーは使わない）。文末は「ぜひお読みください」「あわせてご覧ください」など自然な誘導でよい
- アンカーに使うタイトルは `【2026年最新】` などの装飾や `｜` 以降を省いて自然な形に整えてよい。トピック説明とタイトルが重複してくどい場合は「また、『記事タイトル』もぜひお読みください。」のように簡潔にする
- ※ この「段落分け＋誘導文」は**内部リンク専用**ルール（アフィリリンクとは扱いが違う）。アンカー＝記事タイトルなので、結果として外部リンク同様アンカーにメインKWが入る形になる
- **URLはオーケストレーターから渡された「内部リンク指定」の値をそのまま使う。URLを推測・生成・改変しない。指定が無ければ内部リンクを入れない**（公開URLは日本語スラッグが途中で切れる＆パーセントエンコードされるため、KW・タイトルから復元できない。実URLはKWマスターDBが唯一の正）

記法：丸カッコ `（…）` 内は編集上の操作指示であり**本文には出力しない**。`（段落を分けて）`＝直前で段落を分ける、`（内部リンク）`＝直前のアンカー（記事タイトル）にリンクを張る、の意味。

例（誕生日プレゼントの記事へリンクする場合）：

```
（段落を分けて）
また、彼女への誕生日プレゼントの選び方に関しては、彼女が喜ぶ誕生日プレゼント7選（内部リンク）で解説していますのでぜひお読みください。
```

→ 実際の出力（カッコ内は非表示）：

> また、彼女への誕生日プレゼントの選び方に関しては、[彼女が喜ぶ誕生日プレゼント7選](URL)で解説していますのでぜひお読みください。

### 広告（アフィリエイト）リンク

- アフィリリンクは**指定箇所に限り許可**（外部リンクの「公式・一次情報のみ」原則の例外）。差し込み位置・体裁・広告表記は19章に従う
- **トラッキングURLは推測・生成・改変しない**：オーケストレーターから渡された「アンカー＋正確なURL＋差し込み先」の指定だけを使う。指定が無ければアフィリリンクを入れない（1文字違うと成果が計上されない。内部リンクと同じ厳格管理）
- アンカーテキストはサービス名・固有名詞（「こちら」「詳細はこちら」誘導NG）

## 12. 共起語・E-E-A-T・鮮度

### 共起語・関連語の網羅

- リサーチで抽出した共起語・関連語を本文全体に分散して配置
- 不自然な詰め込みNG（1文に同じKWを2回以上、文脈に合わないKWを無理に入れる）
- H2ごとに異なるサジェストKWを軸にすると自然に分散する

### E-E-A-T

- **Experience**：「実際に使ってみた」「検証した結果」など体験ベースの記述。推測ではなく事実として書く
- **Expertise**：技術的な裏付け・公式仕様の引用・実務Tipsを記述
- **Authoritativeness**：一次情報源（公式サイト・公式ドキュメント・公的統計）を引用
- **Trustworthiness**：情報の鮮度を明示・出典URLを明示

具体的には：
- 数値・スペック・料金は必ず一次ソースから引用（公式ページへのインラインリンク必須）
- 「〜と言われています」「〜らしいです」などの伝聞表現は避ける
- 体験談は「実際に〇〇で試した」「Aプランで生成したところ〜」など具体的に

> **Anniv版の補足：実績が語れない分、専門知識でExpertiseを担保する**（メディア方針/メディア戦略.md 2章）。Annivはまだ実績の量を語れる段階ではないため、「なぜそれが喜ばれるのか」を心理学・マナーなどの一般的な専門知識で裏付ける書き方を積極的に使う（例：「サプライズは"予測できない嬉しさ"が満足度を上げるとされる」のような裏付けを添えてから、具体的な演出案に繋げる）。出典があるものは引用し、一般的な知見として書く場合も伝聞・断定を混同しない。

### 鮮度・時制

- **時制を明示**：「2026年5月時点」「執筆時点（2026年5月）」「現時点では」など
- **ツールの料金・機能・仕様**に言及する箇所では時点が分かるようにする
- **時制注記・確認喚起を全H2・全ブロックに繰り返さない（最頻出の冗長）**：「○年○月時点」「最新は公式で確認してください」を各見出しの末尾に毎回付けると、読者には同じ注意書きの連呼に見える。包括的な「本記事は○年○月時点の情報です。最新は[公式](URL)を確認してください」は**まとめH2末尾に1回だけ**置く（5章）。本文中は、その数値が時点依存で誤解を生む箇所にだけ「○年○月時点」と時点を短く添える程度にとどめ、「最新は公式で確認」の定型文は繰り返さない。未確定情報は「現時点では未公表」「未定」で足り、毎回確認を促さない
- **「最新の」「現在の」などの曖昧表現は避ける**
- 仕様変更が予想される情報も、確認喚起は記事末尾の包括注記に集約する（各所で「変更される可能性があります。公式を確認してください」を繰り返さない）

NG：「〇〇は現在この価格で利用できます」／ 各見出しの末尾に毎回「○年○月時点の情報です。公式で確認してください」を付ける
OK：「〇〇は2026年5月時点でこの価格帯で提供されています」（確認喚起はまとめ末尾に1回集約）

## 17. メタディスクリプション

- 120字前後
- メインKW＋サジェストKW1〜2個を冒頭60字以内に含める
- 結論ベースの要約（「この記事を読むと何が分かるか」を結論で提示）
- CTAは入れない
- **AIっぽい紋切り型の言い回しを使わない（8章の文体ルールをメタにも適用・必須）**：「〜をまとめました」「〜を紹介します」「〜が分かります」「〜を徹底解説」「〜について解説」「ぜひ参考にしてください」などの定型で締めたり並べたりしない。代わりに**具体的な事実（対象アプリ・サービス名／タイプ／数値・料金の幅／可否）を並べ、検索結果で読んで中身が想像できる自然文**にする。語尾を全部「〜ました」で揃えない
- **執筆者は作成しない。レビュアーが最終版とともに生成する**

NG例：「彼女への誕生日プレゼントを7つ徹底解説！選び方や予算をまとめました。ぜひ参考にしてください。」（紋切り型・具体ゼロ・語尾単調）
OK例：「彼女への誕生日プレゼント7つを比較。1万円以下ならアクセサリー、記念日重視なら花束＋手紙が向く。年代・関係性別の相場と選び方の軸で並べた。」（具体名・条件・軸を事実で列挙）

## 19. アフィリエイトリンクと広告表記

アフィリエイトリンクを含む記事の共通ルール。**アフィリ案件を1つも含まない記事には適用しない**（純粋な情報記事・集客記事はこれまで通り）。

> **現状メモ**：Annivは現時点でアフィリ提携をしておらず、収益CVは基本すべて自社送客（無料相談。content-axis.md 軸3のCTAブロック）。この章は将来レストラン予約サイト等の提携が発生した場合のための仕組みとして残してある。案件マスターCSV（`記事管理/アフィリ案件マスター.csv`）は未作成なので、実際にアフィリを始める際に作成する。

### 19-1. 基本原則

- アフィリリンクは**読者が実際にそのサービスを必要とする文脈**でのみ出す。無関係な場所への差し込み・煽り・押し売りはNG（8章のAI臭・誇大表現NGと地続き）
- 1記事の収益地点（着地案件）はオーケストレーターがStep 0で決める。**writerは指定された案件・リンクだけを扱い、自分で案件を増やさない**
- 集客の強い記事と収益の出る記事は一致しない。アフィリ不可のツール（Claude Code本体・Cursor・Midjourney等）は**集客ハブ**として書き切り、内部リンクとCTAで「貼れる代替・関連インフラ・学習」へ送る

### 19-2. リンクの扱い（内部リンクと同じ厳格管理）

- アフィリのトラッキングURLは1文字違うと成果が計上されない。**writerはアフィリURLを推測・生成・改変しない**。オーケストレーターから渡された「アンカー＋正確なURL＋差し込み先」の指定だけを使う（11章「広告（アフィリエイト）リンク」と同じ）
- アンカーテキストはサービス名・固有名詞（「こちら」誘導NG）
- URLの一次ソースは `記事管理/アフィリ案件マスター.csv`（案件名・提携状況・トラッキングURL・バナーHTML・代表報酬＝成果地点 ほか。どの記事に差すかの収益層紐付けは `記事管理/KWマスターDB.csv` の「想定アフィリ案件」列）。**提携状況が「提携済」かつトラッキングURL列に値がある案件のみリンクできる**（未提携・申請中、またはトラッキングURL未発行=空の案件はリンクしない）
- **画像バナーを使う場合は「バナーHTML」列の値を1文字も変えずそのまま設置する**（A8発行の `<a><img>` ＋計測用1x1 gif一式）。`href`・計測gif・`rel="nofollow"` は成果と規約に直結するので改変禁止。**唯一 `alt` だけは記事KWに合わせて書き換えてよい**（成果に無関係・altルール＝画像プレースホルダ節に従う）。バナーHTML列が空の案件はバナー設置しない（テキストリンクのみ）

### 19-3. CTAの差し込み位置と体裁

- 差し込む場所：**ツール紹介H2の直下リード後／操作手順（timeline）の後／まとめH2の後**
- 記事冒頭の `:::summary`（4章）にはアフィリリンクを入れない（あれは結論要約であって誘導ではない）
- 体裁：本文インラインリンク／`:::box` でCTAブロック化／**画像バナー**（案件マスターの「バナーHTML」列がある案件のみ）の3通り。CTAブロックにする場合は `label` に「PR」を含める（例：`:::box color=#1a2840 label="PR｜この構成を試すなら"`）
- **画像バナーの体裁**：バナーHTML列の値をそのまま該当見出しの差し込み先に直置きする（19-2の改変禁止ルール準拠。`alt`のみ記事KWに合わせる）。バナー直上か直下に必ずPR表記を添える（バナー単体でも広告と分かる形にする）。バナーとテキストリンクを同じ案件で二重に並べない（どちらか一方）
- **1記事のCTAは本命案件1つに集約**（サブで関連1つまで）。リンクを乱立させない

### 19-4. アフィリ案件の選び方（ユーザー指定制）

- **アフィリ案件は自動で決めない**。原則オフ（情報記事として書く）。ユーザーが「アフィリ記事にする」と指定し案件を教えてくれた記事だけ差す
- リンクできるのは `記事管理/アフィリ案件マスター.csv` の **提携状況「提携済」かつトラッキングURLが入っている** 案件のみ。指定案件が未提携・申請中、またはトラッキングURL未発行ならアフィリなしで進める
- 差すのは**ユーザー指定の案件だけ**。writer/reviewerは案件を増やさない・別案件に勝手に差し替えない
- 収益層の考え方（参考）：**集客＝「とは/使い方/比較」（母数大・アフィリ不可でも可）→ 成約＝「導入手順/環境構築/学習/自前運用」（指定された高単価案件を集約）**。どの案件を差すかの最終判断はユーザーが行う

### 19-5. 広告表記（景表法・ステマ規制対応／必須）

- アフィリリンクを**1本でも含む記事**は、広告であることを明示する（2023年10月〜の景品表示法・ステマ規制）
- 表記位置：記事冒頭（導入文の直前、または `:::summary` の直後）に「本記事は広告（アフィリエイトプログラム）を含みます」を読者が認識できる形で置く
- frontmatterに `ad: true` を持たせる（保存時。Step 6）
- 表記を小さく隠す・省略するのはNG

### 19-6. レビュー観点

レビュー時のアフィリ・広告チェックは18章チェックリスト「アフィリ・広告表記」に従う（リンクの正確性・読者層マッチ・押し売り・広告表記の有無）。
